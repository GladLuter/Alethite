# Установка Alethite на компьютер с Windows

Этот файл про установку, настройку, обновление и удаление плагина Alethite. Что плагин делает, написано в [README.ru.md](README.ru.md).

Шаги 1-6 из раздела «Установка» проходят быстро: дольше всех строится индекс, несколько минут. Шаг 7 (векторы) идёт часами и может подождать. Всё, что в разделах «Необязательные возможности» и «Только если вы пользовались старой сборкой», можно пропустить.

Все команды в PowerShell.

## Что нужно заранее

- **Десктопное приложение Claude Code**, версия не ниже 2.1.295 (версия движка). Проверка:
  ```powershell
  Get-ChildItem "$env:USERPROFILE\.claude\projects" -Recurse -Filter *.jsonl | Sort-Object LastWriteTime | Select-Object -Last 1 | Get-Content -Tail 50 | Select-String '"version":"([^"]+)"' | Select-Object -Last 1 | ForEach-Object { $_.Matches[0].Groups[1].Value }
  ```
  Команда печатает номер вроде `2.1.300`. Если она ничего не печатает, чатов у вас ещё нет: откройте любой чат, отправьте одно сообщение и запустите команду снова.
- **Python 3.8 или новее и numpy.**
  - Проверка: `python --version` печатает номер версии, а `python -c "import numpy; print(numpy.__version__)"` печатает версию numpy.
  - Python нет: поставьте его с python.org и отметьте «Add python.exe to PATH».
  - Если numpy нет: `python -m pip install numpy`. Запускайте в обычном окне PowerShell, которое вы открыли сами, а не в чате Claude. `pip` из Claude Desktop (сборка из Microsoft Store) ставит пакеты в свою песочницу, и обычный Python их не видит.
- **Ollama с моделью эмбеддингов**, для поиска по смыслу. Необязательно: без неё поиск идёт по одним словам, а добавить её можно позже. Если Ollama ещё нет, поставьте её с ollama.com. После установки она работает в трее. Затем:
  ```powershell
  ollama pull embeddinggemma
  ```
  Это около 622 МБ. Команда заканчивается словом `success`.
- **git.**

## Установка

1. **Скачать код** (ветка `master`):
   ```powershell
   git clone https://github.com/GladLuter/Alethite.git C:\_git\Alethite
   ```
   Эту папку оставьте. Плагин читается прямо из неё, поэтому не переносите и не удаляйте её.
2. **Найти движок десктопа.** `claude` из PATH это отдельный CLI, часто старее, поэтому нужен именно `claude.exe` десктопа. Берётся самый новый файл:
   ```powershell
   $CC = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe", "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Команда должна напечатать путь, который кончается на `claude.exe`. Пустая строка значит, что ничего не нашлось. Первый шаблон для нынешних сборок десктопа, два других для более старых. Если ничего не нашлось, поищите шире (это медленно и может занять несколько минут):
   ```powershell
   $CC = (Get-ChildItem $env:LOCALAPPDATA, $env:APPDATA -Recurse -Filter claude.exe -ErrorAction SilentlyContinue | Where-Object FullName -like '*claude-code*' | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Не закрывайте это окно PowerShell, пока не закончите шаг 3: в новом окне `$CC` пуста.
3. **Поставить плагин:**
   ```powershell
   & $CC plugin marketplace add C:\_git\Alethite
   & $CC plugin install alethite@alethite
   ```
   Каждая команда печатает короткое подтверждение. Ошибка здесь обычно значит, что `$CC` пуста: повторите шаг 2. Затем полностью закройте десктопное приложение (в том числе значок в трее, если он там есть) и откройте его снова.
4. **Собрать индекс** по разговорам этого компьютера (это запись ваших старых чатов, по которой идёт поиск). Первый раз занимает несколько минут:
   ```powershell
   python C:\_git\Alethite\plugin\scripts\cg.py index
   ```
   В конце команда печатает одну строку JSON с итогом.
   - Если вы работаете на двух компьютерах, на этом уже настроена синхронизация (см. «Два компьютера: общая память») и база новая, сначала выполните там `cg.py sync`. Записи и векторы этого компьютера вернутся из его папки, и считать их заново не придётся. Иначе пропустите.
5. **Язык.** По умолчанию плагин говорит по-английски: интерфейс, тексты, которые плагин даёт Claude, и передача дел (краткая сводка старого чата, которая попадает в новый). Сначала откройте новый чат: файл настроек создаётся при первом запуске. Откройте его командой `notepad $env:USERPROFILE\.claude\alethite\settings.json`, поставьте в нём `"language": "ru"` и наберите в поле чата `/reload-plugins`. Для украинского поставьте `"uk"`. Параметр `--lang ru` или `--lang uk` перед `index` задаёт язык сообщений и ошибок скриптов в терминале. Без него они по-английски.
6. **Проверить:** в новом чате наберите `/al-health` в поле чата Claude Code (все команды `/al-...` набираются там). Там должны быть версия, индекс, папка автопамяти, проект, векторы «N из M» и строка синхронизации. «Векторы 0 из N» нормально, пока вы не сделали шаг 7. Строка с ошибкой значит, что один из шагов выше не сработал.
7. **Посчитать векторы.** Необязательно и медленно: это часы. Векторы позволяют поиску находить разговоры по смыслу. Этот шаг можно пропустить сейчас и запустить позже или на ночь. Нужна Ollama с моделью из раздела «Что нужно заранее». На процессоре Intel начального уровня около 25 тысяч кусков истории заняли около 6 часов. После остановки расчёт продолжается с места:
   ```powershell
   python C:\_git\Alethite\plugin\scripts\cg.py embed --max-seconds 100000
   ```
   `--max-seconds 100000` это потолок примерно в 28 часов. Команда останавливается раньше, когда все векторы посчитаны. Дальше новые записи досчитываются сами при старте сессии, до 2 минут за раз.
   - **Ноутбук:** на время расчёта не дайте ему заснуть. На зарядке он засыпает без ввода и останавливает расчёт. После пробуждения запустите команду снова.
   - **Встроенная видеокарта Intel (Iris Xe):** на ней расчёт идёт примерно вдвое быстрее. См. «Полезно знать».

## Обновление

Плагин читается прямо из папки клона, поэтому обновление это `git pull`.

1. Держите клон на ветке `master`. В клоне:
   ```powershell
   cd C:\_git\Alethite
   git pull
   ```
2. Наберите `/reload-plugins` в каждом открытом чате.
3. Проверьте: наберите `/al-health`.

## Удаление Alethite

1. Если фоновая задача включена, выключите её в чате: `/al-job off`.
2. Удалите плагин и его маркетплейс. В новом окне PowerShell `$CC` пуста, поэтому сначала выполните команду из раздела «Установка», шаг 2. Затем:
   ```powershell
   & $CC plugin uninstall alethite@alethite
   & $CC plugin marketplace remove alethite
   ```
   После этого перезапустите десктопное приложение.
3. Если нужно убрать и данные, удалите вручную:
   - `%USERPROFILE%\.claude\alethite`: индекс, `settings.json` с ключом шифрования, передачи дел.
   - Папку индекса, если вы переносили её командой `/al-index-dir`.
   - Подпапку этого компьютера в папке синхронизации (`<папка>\<имя компьютера>`), если вы пользовались синхронизацией.
   - Клон.

   Разговоры самого Claude Code (`%USERPROFILE%\.claude\projects`) и файлы автопамяти остаются нетронутыми.

## Полезно знать

- **Индекс и векторы** лежат в `%USERPROFILE%\.claude\alethite\index.db` и в репозиторий не попадают. Каждый компьютер ведёт свою базу. Общая папка синхронизации только передаёт пачки между ними.
- **Если индекс переехал** командой `/al-index-dir`, он лежит в выбранной папке (см. «Индекс в другой папке»).
- **`/al-index rebuild`** перечитывает все транскрипты и добавляет только недостающее: векторы остаются, ничего не удаляется.
- **Настройки:** свой файл `%USERPROFILE%\.claude\alethite\settings.json`, по одному на компьютер. Он остаётся в этой папке, даже когда индекс переехал. Ключи и их значения по умолчанию перечислены в таблице настроек в [README.ru.md](README.ru.md).
  - Плагин создаёт файл при первом запуске со всеми текущими значениями. Его достаточно открыть и поправить. В файле можно оставить только те ключи, которые вы меняете.
  - Плагин читает файл при каждой загрузке: в начале чата и по `/reload-plugins`. После правки наберите `/reload-plugins`.
  - Значения из файла главнее `/config`. В десктопном приложении у плагинов нет окна настроек, поэтому настройки лежат в файле. `/config` в терминальном `claude` по-прежнему работает, но при расхождении побеждает файл.
  - Обратные слеши в JSON удваиваются: `"Z:\\alethite"`.
  - `/al-health` показывает строку с путём к файлу.
  - Строку `encryptionKey` пишет сам плагин: это ключ шифрования под защитой Windows. Не правьте её.
  - Строку `indexDir` пишет команда `/al-index-dir`. Руками её не правят: файлы индекса сами не переедут.
  - Строку `projectAliases` пишете вы, когда папку проекта переименовали или перенесли: `"projectAliases": {"C:\\work\\new": ["C:\\work\\old"]}`. Новая папка тогда находит разговоры и уроки старой при поиске. Новые разговоры и уроки сохраняются под новой папкой. В индексе ничего не переписывается, в папку синхронизации ничего не уходит, поэтому на каждом компьютере свои псевдонимы. Плагин читает файл при каждом вызове. `/reload-plugins` не нужен. `/config` этот ключ не показывает.
  - Если файл испорчен (неверный JSON), плагин покажет уведомление с именем файла и оставит значения из `/config`. Неизвестный ключ или значение не того типа даёт такое же уведомление, а этот ключ пропускается.
- **Полоса над полем ввода** это одна область на все плагины. Полоса Alethite рисуется в своей рамке с заголовком, а полосы других плагинов остаются под ней.
- **`/al-stats` нужен Obsidian.** Если вы им не пользуетесь, эту команду пропустите. Она пишет через MCP-сервер с именем `obsidian`, у которого есть инструменты `list_vault_files`, `get_note_properties` и `create_vault_file`. Сервер должен быть подключён на этом компьютере.
  - Заметки попадают в папку хранилища, названную на языке мода. По-английски это `Alethite/Measurements` и сводка `Summary.md`, по-русски `Alethite/Замеры` и `Сводка.md`, по-украински `Alethite/Заміри` и `Зведення.md`. Если сменить язык, новые заметки пойдут в новую папку, а старые останутся где были.
  - Если Obsidian недоступен, замер ждёт в очереди и уходит при следующем запуске.
  - Всё остальное в плагине работает без Obsidian.
- **Векторы быстрее на встроенной видеокарте Intel (Iris Xe).** Разовый расчёт (раздел «Установка», шаг 7) идёт на ней примерно вдвое быстрее, а векторы получаются те же (замер 2026-10-19 на ноутбуке: 2,44 длинных куска в секунду против 1,15 на процессоре). Ollama видит такую карту, только если её запустить с `OLLAMA_IGPU_ENABLE=1`. Для этого остановите обычную Ollama в трее, затем в окне PowerShell:
  ```powershell
  $env:OLLAMA_IGPU_ENABLE = '1'; ollama serve
  ```
  В другом окне запустите команду расчёта векторов, а после него закройте это окно и снова запустите Ollama из меню «Пуск». Не оставляйте этот режим включённым: текстовые модели на встроенной карте медленнее.

## Необязательные возможности

Всё, что ниже, до раздела «Только если вы пользовались старой сборкой», необязательно. При первой установке это можно пропустить.

### Фоновая задача

Задача необязательна. Она держит индекс и векторы свежими, пока ни один чат не открыт.

Включайте её на каждом компьютере: в чате `/al-job on` (или `/al-job on 15`, раз в 15 минут).
- Она добавляет в Планировщик заданий Windows задачу «Alethite». Там её можно увидеть и удалить. У неё нет окна, и она работает только пока вы вошли в систему. На батарее векторы ждут, пока ноутбук подключат к питанию.
- Настройки она берёт из того же файла `settings.json`, что и плагин.
- Она запускает `cg.py` установленного плагина. После обновления плагина задача сама переводится на новую копию при старте сессии.
- `/al-job` показывает состояние и последний запуск. `/al-job off` удаляет задачу.
- Если задача не запускается, проверьте, что Python установлен с python.org (рядом с `python.exe` должен лежать `pythonw.exe`).

### Уроки

Уроки работают сами. Claude сохраняет понятую ошибку через `lesson_save`. `/al-lessons` показывает уроки проекта, `/al-lessons forget <pos>` удаляет урок.
- Урок приходит к сообщению, близкому по смыслу, и один раз останавливает команду с его триггером.
- Если уроки приходят не к месту, поднимите `lessonsMinScore` в `settings.json` до `0.55`. Если не приходят никогда, опустите до `0.4`. Выключить: `"lessons": false`.
- Ошибки инструментов из разговоров индексируются с самого начала, поэтому `recall` их находит. После обновления с версии без поиска ошибок один раз перестройте индекс, чтобы в него попали ошибки инструментов из старых разговоров:
  ```powershell
  python C:\_git\Alethite\plugin\scripts\cg.py index --rebuild
  ```
  Перестройка только добавляет недостающее. Векторы для новых записей досчитает фоновая задача или следующий запуск чата.

### Два компьютера: общая память

Это нужно, только если вы пользуетесь Alethite больше чем на одном компьютере.

Каждый компьютер выкладывает свои новые разговоры, векторы и факты автопамяти в общую папку и забирает оттуда чужие. Выкладывает он пачками: пачка это одна выкладка новых записей с одного компьютера.
- Пишет он только в свою подпапку (`<папка>\<имя компьютера>\`), поэтому база не портится, даже если оба компьютера работают одновременно.
- Без сетевой папки всё работает как раньше. Синхронизация догоняет, когда папка снова доступна.

1. **Создать папку** на сетевом диске, один раз, например `\\NAS\share\alethite`. Сам плагин её не создаёт: если диск не подключён, он покажет ошибку, а не начнёт писать на локальный диск.
2. **На каждом компьютере** указать её в файле настроек `%USERPROFILE%\.claude\alethite\settings.json`: `"syncDir": "\\\\NAS\\share\\alethite"`, затем `/reload-plugins`. Обратные слеши в JSON удваиваются.
3. **Первый обмен.** Вся история занимает десятки мегабайт. Плагин синхронизирует не больше 60 секунд за раз и продолжает при следующем запуске, но первый раз удобнее из терминала. Запустите на первом компьютере, затем на втором:
   ```powershell
   python C:\_git\Alethite\plugin\scripts\cg.py sync --sync-dir \\NAS\share\alethite --max-seconds 3600
   ```
   Затем ещё раз на первом, чтобы забрать историю второго. Векторы переезжают вместе с записями: пересчитывать чужие не нужно, если модель эмбеддингов на обоих одна.
4. **Дальше само:** при старте сессии, после индекса и векторов. Вручную: `/al-sync`. Ответ говорит, сколько выложено и влито, и показывает ошибки.
5. **Проверить:** `recall` на втором компьютере находит разговор с первого, а `/al-health` показывает оба компьютера и номера их последних пачек.

Что ещё нужно знать:
- **Короткая память** синхронизируется для проекта текущего чата.
  - Факты, созданные на этом компьютере, уходят в общую папку.
  - Факты другого компьютера копируются в папку автопамяти, если их там нет, и в `MEMORY.md` добавляется строка-указатель.
  - Свой файл с тем же именем никогда не перезаписывается: чужая версия ложится рядом как `имя--КОМПЬЮТЕР.md`. Удалённый вами влитой факт не вернётся.
- **Проект** опознаётся по пути без домашней папки: `C:\Users\Ann\work\x` и `C:\Users\alice\work\x` это один проект. Пути вне профиля (`C:\_git\…`) совпадают и так.

Исправление неполадок, только если что-то сломалось:
- **Испорченная пачка** (обрыв сети, сбой диска) останавливает приём только от её компьютера. Ошибка видна в `/al-health` при каждой синхронизации. Если пачку не восстановить: `/al-sync skip <компьютер> <номер>`. Пропуск виден в `/al-health`.
- **Удалить запись** (например, секрет, который фильтр пропустил) можно только явно, и удаление дойдёт до другого компьютера:
  ```powershell
  python C:\_git\Alethite\plugin\scripts\cg.py forget --conv <id разговора> --pos <pos>
  ```
  `conv` и `pos` берутся из строки находки `recall`. Больше ничего из индекса не исчезает: ни при перестройке, ни когда Claude Code переписывает или удаляет транскрипты.

### Сжатие памяти

Плагин сам сжимает то, что кладёт в контекст модели: выдачу `recall` и `recall_more` и цитаты разговора в передаче дел. Сжатие механическое, без вызовов модели. Код, пути, ссылки, числа, имена и отрицания не трогаются.

- **Уровень:** ключ `"compression"` в файле настроек `%USERPROFILE%\.claude\alethite\settings.json`, затем `/reload-plugins`.
  - `off`: без сжатия.
  - `lite`: пробелы и разметка.
  - `full`: плюс служебные слова.
  - `ultra`: плюс пунктуация и заглавные буквы (по умолчанию).
- **Посмотреть, что делает уровень**, на любом тексте:
  ```powershell
  python C:\_git\Alethite\plugin\scripts\cg.py compress --level ultra --file note.txt
  ```
- **Сколько памяти в контексте:** `/al-stats` пишет в заметку раздел «Память в контексте»: правило памяти, `MEMORY.md`, результаты `recall` и их стоимость, передачи дел. `/al-health` показывает уровень сжатия и размер `MEMORY.md`.
- Если Claude хуже понимает сжатые выдержки, поставьте `full` или `lite`.

### Шифрование

По желанию и только в Windows. В Windows Pro, Enterprise или Education (редакцию показывает Параметры, Система, О системе) проще всего пара: `efs` для индекса и `cryptography` для папки синхронизации, как в примере в шаге 1. Этой паре не нужен дополнительный пакет.

Два термина. Пачка: одна выкладка новых записей с одного компьютера. Поколение: полный набор подпапки компьютера в одном шифре (`gen-0001`, `gen-0002` и так далее). Включение или выключение шифрования и смена шифра начинают новое.

Шифруются индекс (с его резервной копией `index.before-stage2.db`, если она есть) и всё, что компьютер кладёт в папку синхронизации. В папке читаются имя компьютера, номера, число и размеры пачек, а в метке поколения (`gen-0001\generation.json`) ещё название способа шифрования, отпечаток ключа и дата. По отпечатку ключ не узнать.
- Ключ лежит в `settings.json` под защитой Windows (DPAPI). На другом компьютере или под другой учётной записью Windows этот файл ключа не даст.
- Пока вы не набрали `/al-encrypt on`, у вас ничего не меняется.

**Способы шифрования.** Индекс и папка синхронизации шифруются каждый своим способом, и каждый компьютер выбирает их сам:
- Индекс, ключ `indexCipher`:
  - `sqlcipher` (по умолчанию): SQLCipher, нужен пакет `sqlcipher3`.
  - `efs`: шифрование файлов самой Windows. Нужны Windows Pro (или Enterprise, Education) и диск NTFS. Пакеты ставить не надо. Под EFS уходит вся папка плагина `%USERPROFILE%\.claude\alethite` и папка индекса, если она другая: индекс, журнал, резервные копии, передачи дел, `settings.json`, `forgotten.json`.
- Папка синхронизации, ключ `shareCipher`:
  - `sqlcipher` (по умолчанию): SQLCipher, нужен пакет `sqlcipher3`.
  - `cryptography`: AES-GCM, встроен в Windows (`bcrypt.dll`). Пакет `cryptography` больше не нужен.
- **Smart App Control** может не дать загрузить `sqlcipher3`, потому что его модуль не подписан. Под ним годятся только `efs` и `cryptography`, а компьютеру с этой парой `sqlcipher3` не нужен. Исключения: перевод уже существующего индекса SQLCipher и чтение папки компьютера, который пишет SQLCipher.
- Свою подпапку в папке синхронизации каждый компьютер пишет своим способом, а чужие читает по метке поколения. Если чужая подпапка записана SQLCipher, а здесь `sqlcipher3` не загружается, `/al-health` называет тот компьютер и советует перевести его на AES-GCM.

1. **Выбрать способы** на каждом компьютере в `%USERPROFILE%\.claude\alethite\settings.json`. Например, EFS и AES-GCM:
   ```json
   {
     "indexCipher": "efs",
     "shareCipher": "cryptography"
   }
   ```
   Если ничего не выбирать, в обоих остаётся `sqlcipher`. `/al-encrypt on` и `join` берут способы из этого файла и записывают их обратно рядом с ключом. Плагин читает файл при загрузке, поэтому правьте его до `/reload-plugins` в следующих шагах.
2. **Поставить пакет `sqlcipher3`**, только если он нужен: для способа `sqlcipher` (индекса или папки) и один раз для перевода уже зашифрованного индекса SQLCipher в EFS. Ставьте на каждом компьютере из обычного окна PowerShell, не изнутри Claude: `pip` из Claude кладёт пакеты в свою песочницу, и фоновая задача их не увидит.
   ```powershell
   python -m pip install sqlcipher3
   ```
3. **Первый компьютер:** `/reload-plugins`, затем `/al-encrypt on`. Окна «Alethite» могут оказаться за другими окнами.
   - С `efs` команда сначала проверяет, что диск умеет EFS. Если нет (Windows Home или диск не NTFS), она откажет до создания ключа, ничего не изменив.
   - С `efs` индексу нужна и своя папка. EFS зашифровал бы всё, что в ней лежит, поэтому если папка индекса не совпадает с папкой плагина и в ней есть чужие файлы, команда откажет до создания ключа. Перенесите индекс в отдельную папку командой `/al-index-dir` и повторите.
   - В первом окне будет **код восстановления**. Он показывается один раз. Ctrl+C копирует текст окна: вставьте код в менеджер паролей. Без него зашифрованную историю не прочитать, если пропадут компьютеры или их учётные записи Windows.
   - Вопрос «Код восстановления сохранён?»: по умолчанию «Нет». Шифрование начнётся только после «Да».
   - Индекс и его резервная копия шифруются. С `sqlcipher` открытые копии (`index.db.plain`) удаляются только после «Да». При «Нет» они остаются, и `/al-encrypt on` спросит снова.
   - С `efs` папка плагина и папка индекса уходят под шифрование Windows, а индекс SQLCipher превращается в обычную базу под EFS со страницами 16 КБ. Открытой копии вне EFS не бывает, поэтому вопроса про `index.db.plain` нет.
   - Папка синхронизации: компьютер выкладывает свою подпапку заново, выбранным способом. Прежние данные в ней (открытые или другим способом) удаляются только после «Да» и только когда новые выложены полностью.
4. **Второй компьютер:** `git pull`, свои способы в `settings.json` (шаг 1), `/reload-plugins`, `/al-encrypt join`. Код восстановления вводится в окне со скрытым вводом. Ключ один на все компьютеры, поэтому `on` на втором откажется и подскажет `join`.
   - Если на первом компьютере вы меняете способ папки (например, SQLCipher на AES-GCM), присоединяйте второй только после этого. Иначе он увидит поколение SQLCipher, которое под Smart App Control не откроет.
5. **Проверить:** `/al-health` на обоих компьютерах пишет, например, «Шифрование: включено (индекс: EFS, папка синхронизации: AES-GCM)». Если что-то не доделано, строки под ней скажут, что повторить. Одно только состояние показывает `/al-encrypt status`.

Что ещё нужно знать:
- **Команды:** `/al-encrypt on | join | off | status`. Без аргумента выполняется `status`.
  - `off` расшифровывает индекс (с EFS снимает шифрование Windows с обеих папок), выкладывает подпапку этого компьютера открытой и убирает ключ из `settings.json`. Выключать нужно на каждом компьютере. Новый `on` создаёт новый ключ, остальные компьютеры присоединяются заново.
  - Потеряли ключ (другая учётная запись Windows, переустановка): `/al-encrypt join` с кодом восстановления.
  - Потеряли и ключ, и код: этот компьютер своё зашифрованное уже не прочитает. Выключите шифрование (`off`) на остальных компьютерах и вручную удалите папку этого компьютера в папке синхронизации, а если на нём остался зашифрованный `index.db`, то и его (плагин соберёт новый из разговоров на диске). Потом включите шифрование заново: `on` на одном компьютере, `join` с новым кодом на остальных.
- **Пока второй компьютер не присоединился**, первый ничего от него не берёт, а `/al-health` называет его: «выполните на нём `join`». История второго не теряется: после `join` он выложит её зашифрованной.
- **Предел времени.** Один запуск ограничен примерно 10 минутами (предел десктопного приложения). Большая первая выкладка может не уложиться: ответ скажет, что не закончено. Повторите `/al-encrypt on` (или `join`): команда продолжит с того места, где остановилась. Любой шаг можно безопасно повторить. Остаток выложит и фоновая задача, но прежние открытые данные из папки удалит только повтор команды, после «Да».
- **Способы шифрования** задают ключи `indexCipher` (`sqlcipher` по умолчанию или `efs`) и `shareCipher` (`sqlcipher` по умолчанию или `cryptography`, то есть AES-GCM) в `settings.json`. `/al-encrypt on` и `join` сами записывают их в файл, а файл главнее `/config`, поэтому позже меняйте их в файле, затем `/reload-plugins` и `/al-encrypt on`. Чужие данные компьютер читает любым способом, который умеет открывать сам: SQLCipher только при установленном `sqlcipher3`.
- **Скорость.** На зашифрованном индексе `recall` медленнее примерно на 0,08 с (24,7 тыс. векторов), и разница растёт с числом векторов. Один поиск по 25,3 тыс. векторов занимает 290 мс с SQLCipher и 170 мс с EFS.
- **Что принимается вместе с EFS:**
  - Копия индекса на флешку FAT или exFAT, в сеть или программой, которая читает файл и пишет его заново вне EFS, получается открытой. Сам плагин индекс наружу не копирует.
  - Файлы открываются только под той же учётной записью Windows. Если индекс под EFS не открывается, плагин скажет об этом и новый пустой индекс поверх не создаст.
  - После переустановки Windows без копии сертификата EFS прежний индекс не открыть: удалите его, и плагин соберёт новый из разговоров на диске. Копия сертификата по желанию, плагин её не делает. Чтобы сделать её, выполните `cipher /x <файл>`: Windows спросит пароль и сохранит сертификат EFS и ключ в файл `.pfx`, защищённый этим паролем.
- **Остаётся открытым:**
  - Разговоры Claude Code, `%USERPROFILE%\.claude\projects\*.jsonl`.
  - Файлы автопамяти каждого проекта на локальном диске (`.md`): их читает Claude Code.
  - Передачи дел, папка `handoffs` рядом с индексом: тот же текст уходит в чат открытым. С EFS сами файлы на диске зашифрованы.
  - `forgotten.json` в `%USERPROFILE%\.claude\alethite`, его создают только для индекса в другой папке: ключи записей, удалённых через `forget`. Это хеши, текста в них нет.

### Индекс в другой папке

Для компьютера, где на C: мало места. Индекс растёт с каждым чатом, и его можно перенести на другой локальный диск. Только Windows. Без этой команды ничего не меняется, индекс лежит в `%USERPROFILE%\.claude\alethite\`.

1. **Переехать:** `/al-index-dir D:\Alethite`. Без пути откроется окно выбора папки.
   - Команда копирует индекс, сверяет копию и после этого переключает плагин на новую папку. Если индекс занят чатом или фоновой задачей, она просит повторить через минуту.
   - Затем окно спрашивает, удалить ли старую копию. По умолчанию «Нет». Старые файлы удаляются только после «Да». После «Нет» они остаются, а `/al-health` напоминает, где они лежат. Чтобы спросить снова, повторите `/al-index-dir` с той же папкой.
2. **Проверить:** `/al-health`. В строке «Индекс» теперь новый путь, например `D:\Alethite\index.db`.

Фоновая задача и инструменты `recall` и `lesson_save` сами работают с новой папкой. Ничего переустанавливать не нужно.

Что ещё нужно знать:
- **Что переезжает:** `index.db`, его резервная копия `index.before-stage2.db` (если есть), папка `handoffs` и `job.xml` фоновой задачи. Зашифрованный индекс переезжает зашифрованным. Индекс под EFS остаётся под EFS: целевая папка шифруется до копирования.
- **Что остаётся на C:** файл `settings.json` (в нём ключ шифрования и новая строка `indexDir`) и разговоры Claude Code, `%USERPROFILE%\.claude\projects`.
- **Отказ.** Команда ничего не меняет и называет причину, если:
  - папка не на локальном несъёмном диске (сетевые пути, сетевые и съёмные диски не подходят) или лежит внутри OneDrive
  - в папке уже есть другой `index.db`, чужую базу команда не перезаписывает
  - на целевом диске не хватает места, нужен размер файлов индекса и ещё 200 МБ
  - рядом с индексом лежит `index.db.plain`, сначала доведите до конца `/al-encrypt on`
  - индекс под EFS, а диск папки не умеет шифровать файлы (нужен NTFS): выберите папку на диске NTFS или сначала выключите шифрование (`/al-encrypt off`)
  - на C: ещё не слиты записи за время, пока папки не было (см. ниже).
- **Если папки или `index.db` в ней не стало** (диск отключили, папку удалили), плагин говорит об этом уведомлением, один раз за сессию, и строкой в `/al-health`: «индекс в D:\Alethite недоступен, сейчас работаю с …». Он работает с индексом на C:, а `indexDir` не меняет.
  - Если в стандартной папке уже лежит индекс (старая копия после «Нет»), работа идёт с ним. Если нет, новый создаётся только когда на C: свободно не меньше 2 ГБ. Иначе команды, которым нужен индекс, отвечают ошибкой с путями и цифрами, и ничего не создаётся. Команды без индекса работают: передача дел кнопки «Новый работник», подсчёт токенов и предпросмотр сжатия. Пока так, в строке состояния стоит «Индекс недоступен, подробности в /al-health», а на каждое ваше сообщение приходит уведомление с причиной.
  - Синхронизация идёт как обычно.
  - Удалённое через `forget` остаётся удалённым и на C:. Его ключи лежат в `forgotten.json` рядом с `settings.json`, и индекс на C: применяет их раньше, чем прочитает хоть один разговор.
- **Когда папка вернулась**, первый же запуск `cg.py` (фоновая задача или команда в чате) сам вливает в неё всё, что накопилось на C:, и удаляет временный индекс. Без вопроса, место на C: дороже. Старая копия, которую вы оставили ответом «Нет» и которая заменяла индекс на время сбоя, вливается и удаляется так же. Сообщение называет число влитых записей, и `/al-health` его хранит. Удалённое через `forget` не возвращается. Если слияние не сошлось, оба индекса остаются на месте, работа идёт с папкой индекса, `/al-health` показывает причину, а следующий запуск пробует снова.
- **Папка не вернётся.** Пока плагин работает с C:, команда с полным путём стандартной папки, `/al-index-dir C:\Users\<имя>\.claude\alethite`, убирает `indexDir` и ничего не копирует. C: становится постоянным местом индекса. Если папка вернулась, а индекса в ней нет, команда с путём этой папки переносит индекс с C: в неё.
- **Вернуть индекс на C:** из рабочей папки его переносит та же команда, `/al-index-dir C:\Users\<имя>\.claude\alethite`. Если на C: осталась старая копия, не совпадающая с индексом байт в байт, команда откажет. Тогда сначала повторите `/al-index-dir` с рабочей папкой и ответьте «Да» на вопрос об удалении. Копия, совпадающая байт в байт, переезд не останавливает.
- **Слияние не получается раз за разом.** `/al-health` показывает причину в своей строке, а `/al-index-dir` отказывает, пока слияние не сделано. Если причина повторяется каждый раз, удалите `index.db` в `C:\Users\<имя>\.claude\alethite` вручную, но только когда сохранённые там записи уже не нужны. Индекс в рабочей папке остаётся как есть.

## Только если вы пользовались старой сборкой

Новым пользователям этот раздел не нужен.

### С alethite@alethite-local

Для установок, сделанных до переименования маркетплейса. Теперь идентификатор плагина `alethite@alethite`, а маркетплейс называется `alethite`.

1. Задайте `$CC` (в новом окне PowerShell она пуста):
   ```powershell
   $CC = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe", "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Если ничего не нашлось, используйте поиск шире из раздела «Установка», шаг 2.
2. Уберите старую регистрацию и сделайте новую:
   ```powershell
   & $CC plugin uninstall alethite@alethite-local
   & $CC plugin marketplace remove alethite-local
   & $CC plugin marketplace add C:\_git\Alethite
   & $CC plugin install alethite@alethite
   ```
3. Наберите `/reload-plugins` в каждом открытом чате, затем `/al-health`.

Папка с данными и `settings.json` остаются на месте. Значения, которые вы задали через `/config` под старым идентификатором, не переносятся. Проверьте их в плагине и задайте заново то, что ещё нужно.

### С CacheGuard

Плагин раньше назывался Claude-CacheGuard, так же назывался и репозиторий. Это была прежняя закрытая сборка. Компьютер со старым плагином переводится по шагам ниже. Порядок важен.

0. **Отправить ожидающие замеры.** В чате один раз наберите `/cg-stats`. Замеры, которые Obsidian ещё не принял, лежат в хранилище старого плагина и пропадут вместе с ним.
1. **Убрать старый плагин.** В новом окне PowerShell `$CC` пуста. Задайте её, как в разделе «Установка», шаг 2 (если путь не нашёлся, там же поиск шире), и уберите старый плагин:
   ```powershell
   $CC = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe", "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   & $CC plugin uninstall cacheguard@cacheguard-local
   & $CC plugin marketplace remove cacheguard-local
   ```
2. **Поставить новый.** Если клона в `C:\_git\Alethite` ещё нет, сначала склонируйте его (раздел «Установка», шаг 1). Затем:
   ```powershell
   & $CC plugin marketplace add C:\_git\Alethite
   & $CC plugin install alethite@alethite
   ```
3. **Перезагрузить.** Наберите `/reload-plugins` в каждом открытом чате. Чат без перезагрузки продолжит работать старым плагином и может снова завести старую папку.
4. **Проверить.** Наберите `/al-health`. Первый вызов переносит папку плагина `%USERPROFILE%\.claude\cacheguard` в `%USERPROFILE%\.claude\alethite`, а вместе с ней индекс, ключ, настройки и передачи дел. Если фоновая задача была включена, старая задача Планировщика «CacheGuard» удаляется, а задача «Alethite» создаётся с тем же интервалом. В ответе посмотрите индекс, ключ, синхронизацию и задачу.
   - Если папку перенести не вышло, ответ назовёт причину. Плагин пока работает в старой папке, а следующий запуск попробует снова.
   - Если старая папка осталась рядом с новой, её снова создал чат со старым плагином. Ничего не перенесено. Проверьте старую папку и удалите её.
   - Индекс, который вы переносили командой `/al-index-dir`, остаётся на месте. Переезжает только папка плагина.
   - Папка синхронизации продолжает работать под старым именем. Путь в `syncDir` задали вы сами, переименование его не трогает, папку на диске переименовывать не нужно.
5. **Сохранить память прежней папки проекта.** Клон теперь лежит в другой папке, и поиск из неё не найдёт старые разговоры проекта. Добавьте в `%USERPROFILE%\.claude\alethite\settings.json` эту строку:
   ```json
   "projectAliases": { "C:\\_git\\Alethite": ["C:\\_git\\Claude-CacheGuard"] }
   ```
   Вставьте её внутрь внешних фигурных скобок файла, а после предыдущей строки поставьте запятую. Файл целиком не заменяйте: в нём ваши остальные настройки и, если шифрование включено, ключ шифрования. Плагин читает файл при каждом вызове. Затем проверьте, что `recall` в чате, открытом в `C:\_git\Alethite`, находит старые разговоры проекта.

Значения, которые вы задали через `/config` под старым плагином, не переносятся. Проверьте их в новом плагине и задайте заново то, что ещё нужно. Всё, что лежит в `settings.json`, переезжает вместе с папкой.
