# Установка CacheGuard на компьютер с Windows

Все команды — в PowerShell.

## Что нужно заранее

- **Десктопное приложение Claude Code**, движок не ниже 2.1.295. Проверка версии:
  ```powershell
  Get-ChildItem "$env:USERPROFILE\.claude\projects" -Recurse -Filter *.jsonl | Sort-Object LastWriteTime | Select-Object -Last 1 | Get-Content -Tail 50 | Select-String '"version":"([^"]+)"' | Select-Object -Last 1 | ForEach-Object { $_.Matches[0].Groups[1].Value }
  ```
- **Python 3.8 или новее и numpy.** Проверка: `python -c "import numpy; print(numpy.__version__)"`. Если numpy нет: `python -m pip install numpy`. Ставить из обычного окна PowerShell, не изнутри Claude: `pip` из Claude Desktop (сборка из Microsoft Store) ставит пакеты в свою песочницу, и обычный Python их не видит.
- **Ollama с моделью эмбеддингов**, нужна для поиска по смыслу. Если Ollama ещё нет, поставить её с ollama.com. Затем:
  ```powershell
  ollama pull embeddinggemma
  ```
  Это около 622 МБ. Без модели мод работает, только поиск идёт по одним словам.
- **git.**

## Установка

1. **Скачать код** (ветка `master`):
   ```powershell
   git clone https://github.com/GladLuter/Claude-CacheGuard.git C:\_git\Claude-CacheGuard
   cd C:\_git\Claude-CacheGuard
   ```
2. **Найти движок десктопа.** `claude` из PATH — отдельный CLI, часто старее, поэтому нужен именно `claude.exe` десктопа:
   ```powershell
   $CC = (Get-ChildItem "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Если ничего не нашлось, искать шире (это медленно):
   ```powershell
   $CC = (Get-ChildItem $env:LOCALAPPDATA, $env:APPDATA -Recurse -Filter claude.exe -ErrorAction SilentlyContinue | Where-Object FullName -like '*claude-code*' | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
3. **Поставить мод:**
   ```powershell
   & $CC plugin marketplace add C:\_git\Claude-CacheGuard
   & $CC plugin install cacheguard@cacheguard-local
   ```
   Затем перезапустить десктопное приложение.
4. **Собрать индекс** по разговорам этого компьютера. Первый раз занимает несколько минут:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py --lang ru index
   ```
   `--lang ru` — язык сообщений и ошибок скриптов в терминале (`en`, `ru`, `uk`); без него они по-английски. Если на компьютере уже настроена синхронизация (раздел ниже), а база новая, сначала выполните там `cg.py sync`: записи и векторы этого компьютера вернутся из его папки, и считать их заново не придётся.
5. **Посчитать векторы.** Это часы: на i3 вся история заняла около 6 часов, лучше запускать на ночь. После остановки расчёт продолжается с места:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py --lang ru embed --max-seconds 100000
   ```
   Дальше новые записи досчитываются сами при старте сессии, до 2 минут за раз.
   - **Ноутбук:** на время расчёта не дайте ему заснуть. На зарядке он засыпает без ввода и останавливает расчёт. После пробуждения команду можно просто запустить снова.
   - **Встроенная видеокарта Intel (Iris Xe):** на ней разовый расчёт идёт примерно вдвое быстрее, а векторы получаются те же (замер 2026-10-19 на MTLAPTOP: 2,44 длинных куска в секунду против 1,15 на процессоре). Ollama видит такую карту, только если её запустить с `OLLAMA_IGPU_ENABLE=1`. Для этого остановите обычную Ollama в трее, затем в окне PowerShell:
     ```powershell
     $env:OLLAMA_IGPU_ENABLE = '1'; ollama serve
     ```
     В другом окне запустите расчёт, а после него закройте это окно и снова запустите Ollama из меню «Пуск». Насовсем не включать: текстовые модели на встроенной карте медленнее.
6. **Язык.** По умолчанию мод говорит по-английски: интерфейс, правило памяти, описания `recall` и передача дел. Для русского откройте файл настроек `%USERPROFILE%\.claude\cacheguard\settings.json` (мод создал его при первом запуске), поставьте в нём `"language": "ru"` и наберите `/reload-plugins`. Для украинского поставьте `"uk"`.
7. **Проверить:** в новом чате набрать `/cg-health`. Там должны быть версия, индекс, папка автопамяти, проект, векторы «N из M» и строка синхронизации.

## Общая память двух компьютеров (этап 2)

Каждый компьютер выкладывает свои новые разговоры, векторы и факты автопамяти в общую папку и забирает оттуда чужие. Пишет он только в свою подпапку (`<папка>\<имя компьютера>\`), поэтому база не портится, даже если оба компьютера работают одновременно. Без сетевой папки всё работает как раньше; синхронизация догоняет, когда папка снова доступна.

1. **Создать папку** на сетевом диске, один раз, например `\\NAS\share\cacheguard`. Сам мод её не создаёт: если диск не подключён, он покажет ошибку, а не начнёт писать на локальный диск.
2. **На каждом компьютере** указать её в файле настроек `%USERPROFILE%\.claude\cacheguard\settings.json`: `"syncDir": "\\\\NAS\\share\\cacheguard"`, затем `/reload-plugins`. Обратные слеши в JSON удваиваются.
3. **Первый обмен.** Вся история — это десятки мегабайт. Мод синхронизирует не больше 60 секунд за раз и продолжает при следующем запуске, но первый раз удобнее из терминала, сначала на i3, потом на ноутбуке:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py --lang ru sync --sync-dir \\NAS\share\cacheguard --max-seconds 3600
   ```
   Затем на i3 ещё раз, чтобы забрать историю ноутбука. Векторы переезжают вместе с записями: пересчитывать чужие не нужно, если модель эмбеддингов на обоих одна.
4. **Дальше само:** при старте сессии, после индекса и векторов. Вручную — `/cg-sync`, ответ — сколько выложено и влито и ошибки.
5. **Проверить:** `recall` на ноутбуке находит утренний разговор с i3, а `/cg-health` показывает оба компьютера и номера их последних пачек.

Что ещё нужно знать:
- **Короткая память** синхронизируется для проекта текущего чата: факты, созданные на этом компьютере, уходят в общую папку; чужие копируются в папку автопамяти, если их там нет, и в `MEMORY.md` добавляется строка-указатель. Свой файл с тем же именем никогда не перезаписывается: чужая версия ложится рядом как `имя--КОМПЬЮТЕР.md`. Удалённый вами влитой факт не вернётся.
- **Проект** опознаётся по пути без домашней папки: `C:\Users\AIJ\work\x` и `C:\Users\gladl\work\x` — один проект. Пути вне профиля (`C:\_git\…`) совпадают и так.
- **Испорченная пачка** (обрыв сети, сбой диска) останавливает приём только от её компьютера, ошибка видна в `/cg-health` при каждой синхронизации. Если пачку не восстановить: `/cg-sync skip <компьютер> <номер>`. Пропуск виден в `/cg-health`.
- **Удалить запись** (например, секрет, который фильтр пропустил) можно только явно, и удаление дойдёт до другого компьютера:
  ```powershell
  python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py forget --conv <id разговора> --pos <pos>
  ```
  `conv` и `pos` — из строки находки `recall`. Больше ничего из индекса не исчезает: ни при перестройке, ни когда Claude Code переписывает или удаляет транскрипты.

## Сжатие памяти (этап 3)

Мод сжимает то, что сам кладёт в контекст модели: выдачу `recall` и `recall_more` и цитаты разговора в передаче дел. Сжатие механическое, без вызовов модели. Код, пути, ссылки, числа, имена и отрицания не трогаются.

- **Уровень:** ключ `"compression"` в файле настроек `%USERPROFILE%\.claude\cacheguard\settings.json`, затем `/reload-plugins`.
  - `off` — без сжатия;
  - `lite` — пробелы и разметка;
  - `full` — плюс служебные слова;
  - `ultra` — плюс пунктуация и заглавные буквы (по умолчанию).
- **Посмотреть, что делает уровень**, на любом тексте:
  ```powershell
  python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py compress --level ultra --file заметка.txt
  ```
- **Сколько памяти в контексте:** `/cg-stats` пишет в заметку раздел «Память в контексте» — правило памяти, `MEMORY.md`, результаты `recall` и их стоимость, передачи дел. `/cg-health` показывает уровень сжатия и размер `MEMORY.md`.
- Если работник хуже понимает сжатые выдержки, поставьте `full` или `lite`.

## Уроки, фоновая задача, поиск ошибок (этап 4)

После `git pull` и `/reload-plugins`:

1. **Один раз перестроить индекс**, чтобы в него попали ошибки инструментов из старых разговоров:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py index --rebuild
   ```
   Перестройка только добавляет недостающее. Векторы для новых записей досчитает фоновая задача или следующий запуск чата.
2. **Включить фоновую задачу** на каждом компьютере: в чате `/cg-job on` (или `/cg-job on 15` — раз в 15 минут).
   - Появится задача «CacheGuard» в Планировщике заданий: без окна, только пока вы вошли в систему, на батарее векторы ждут сети.
   - Настройки она берёт из того же файла `settings.json`, что и мод.
   - `/cg-job` показывает состояние и последний запуск, `/cg-job off` удаляет задачу.
   - Если задача не запускается, проверьте, что Python установлен с python.org (рядом с `python.exe` должен лежать `pythonw.exe`).
3. **Уроки** работают сами: работник сохраняет понятую ошибку через `lesson_save`. `/cg-lessons` показывает уроки проекта, `/cg-lessons forget <pos>` удаляет урок.
   - Урок приходит к сообщению, близкому по смыслу, и останавливает один раз команду с его триггером.
   - Если уроки приходят не к месту, поднимите `lessonsMinScore` в `settings.json` до `0.55`; если не приходят никогда — опустите до `0.4`. Выключить — `"lessons": false`.

## Шифрование (этап 5)

По желанию и только в Windows. Шифруются индекс (с его резервной копией `index.before-stage2.db`) и всё, что компьютер кладёт в папку синхронизации. В папке читаются имя компьютера, номера, число и размеры пачек, а в метке поколения (`gen-0001\generation.json`) ещё название способа шифрования, отпечаток ключа и дата. По отпечатку ключ не узнать.
- Ключ лежит в `settings.json` под защитой Windows (DPAPI). На другом компьютере или под другой учётной записью Windows этот файл ключа не даст.
- Пока вы не набрали `/cg-encrypt on`, у вас ничего не меняется.

**Способы шифрования.** Индекс и папка синхронизации шифруются каждый своим способом, и каждый компьютер выбирает их сам:
- Индекс, ключ `indexCipher`:
  - `sqlcipher` (по умолчанию): SQLCipher, нужен пакет `sqlcipher3`;
  - `efs`: шифрование файлов самой Windows. Нужны Windows Pro (или Enterprise, Education) и диск NTFS. Пакеты ставить не надо. Под EFS уходит вся папка мода `%USERPROFILE%\.claude\cacheguard` и папка индекса, если она другая: индекс, журнал, резервные копии, передачи дел, `settings.json`, `forgotten.json`.
- Папка синхронизации, ключ `shareCipher`:
  - `sqlcipher` (по умолчанию): SQLCipher, нужен пакет `sqlcipher3`;
  - `cryptography`: AES-GCM, встроен в Windows (`bcrypt.dll`). Пакет `cryptography` больше не нужен.
- **Smart App Control** может не дать загрузить `sqlcipher3`: его модуль не подписан. Под ним годятся только `efs` и `cryptography`, а компьютеру с этой парой `sqlcipher3` не нужен. Исключения: перевод уже существующего индекса SQLCipher и чтение папки компьютера, который пишет SQLCipher.
- Свою подпапку в папке синхронизации каждый компьютер пишет своим способом, а чужие читает по метке поколения. Если чужая подпапка записана SQLCipher, а здесь `sqlcipher3` не загружается, `/cg-health` называет тот компьютер и советует перевести его на AES-GCM.

1. **Выбрать способы** на каждом компьютере в `%USERPROFILE%\.claude\cacheguard\settings.json`. Например, EFS и AES-GCM:
   ```json
   {
     "indexCipher": "efs",
     "shareCipher": "cryptography"
   }
   ```
   Если ничего не выбирать, в обоих остаётся `sqlcipher`. `/cg-encrypt on` и `join` берут способы из этого файла и записывают их обратно рядом с ключом. Мод читает файл при загрузке, поэтому правьте его до `/reload-plugins` в следующих шагах.
2. **Поставить пакет `sqlcipher3`**, только если он нужен: для способа `sqlcipher` (индекса или папки) и один раз для перевода уже зашифрованного индекса SQLCipher в EFS. Ставьте на каждом компьютере из обычного окна PowerShell, не изнутри Claude: `pip` из Claude кладёт пакеты в свою песочницу, и фоновая задача их не увидит.
   ```powershell
   python -m pip install sqlcipher3
   ```
3. **Первый компьютер:** `/reload-plugins`, затем `/cg-encrypt on`. Окна «Claude-CacheGuard» могут оказаться за другими окнами.
   - С `efs` команда сначала проверяет, что диск умеет EFS. Если нет (Windows Home или диск не NTFS), она откажет до создания ключа, ничего не изменив.
   - В первом окне будет **код восстановления**. Он показывается один раз. Ctrl+C копирует текст окна: вставьте код в менеджер паролей. Без него зашифрованную историю не прочитать, если пропадут компьютеры или их учётные записи Windows.
   - Вопрос «Код восстановления сохранён?»: по умолчанию «Нет». Шифрование начнётся только после «Да».
   - Индекс и его резервная копия шифруются. С `sqlcipher` открытые копии (`index.db.plain`) удаляются только после «Да». При «Нет» они остаются, и `/cg-encrypt on` спросит снова.
   - С `efs` папка мода и папка индекса уходят под шифрование Windows, а индекс SQLCipher превращается в обычную базу под EFS со страницами 16 КБ. Открытой копии вне EFS не бывает, поэтому вопроса про `index.db.plain` нет.
   - Папка синхронизации: компьютер выкладывает свою подпапку заново, выбранным способом. Прежние данные в ней (открытые или другим способом) удаляются только после «Да» и только когда новые выложены полностью.
4. **Второй компьютер:** `git pull`, свои способы в `settings.json` (шаг 1), `/reload-plugins`, `/cg-encrypt join`. Код восстановления вводится в окне со скрытым вводом. Ключ один на все компьютеры, поэтому `on` на втором откажется и подскажет `join`.
   - Если на первом компьютере вы меняете способ папки (например, SQLCipher на AES-GCM), присоединяйте второй только после этого. Иначе он увидит поколение SQLCipher, которое под Smart App Control не откроет.
5. **Проверить:** `/cg-health` на обоих компьютерах пишет, например, «Шифрование: включено (индекс: EFS, папка синхронизации: AES-GCM)». Если что-то не доделано, строки под ней скажут, что повторить. Одно только состояние показывает `/cg-encrypt status`.

Что ещё нужно знать:
- **Команды:** `/cg-encrypt on | join | off | status`. Без аргумента выполняется `status`.
  - `off` расшифровывает индекс (с EFS снимает шифрование Windows с обеих папок), выкладывает подпапку этого компьютера открытой и убирает ключ из `settings.json`. Выключать нужно на каждом компьютере. Новый `on` создаёт новый ключ, остальные компьютеры присоединяются заново.
  - Потеряли ключ (другая учётная запись Windows, переустановка): `/cg-encrypt join` с кодом восстановления.
  - Потеряли и ключ, и код: этот компьютер своё зашифрованное уже не прочитает. Выключите шифрование (`off`) на остальных компьютерах и вручную удалите папку этого компьютера в папке синхронизации, а если на нём остался зашифрованный `index.db`, то и его (мод соберёт новый из разговоров на диске). Потом включите шифрование заново: `on` на одном компьютере, `join` с новым кодом на остальных.
- **Пока второй компьютер не присоединился**, первый ничего от него не берёт, а `/cg-health` называет его: «выполните на нём `join`». История второго не теряется: после `join` он выложит её зашифрованной.
- **Предел времени.** Один запуск ограничен примерно 10 минутами (предел десктопного приложения). Большая первая выкладка может не уложиться: ответ скажет, что не закончено. Повторите `/cg-encrypt on` (или `join`): команда продолжит с того места, где остановилась. Любой шаг можно безопасно повторить. Остаток выложит и фоновая задача, но прежние открытые данные из папки удалит только повтор команды, после «Да».
- **Способы шифрования** задают ключи `indexCipher` (`sqlcipher` по умолчанию или `efs`) и `shareCipher` (`sqlcipher` по умолчанию или `cryptography`, то есть AES-GCM) в `settings.json`. `/cg-encrypt on` и `join` сами записывают их в файл, а файл главнее `/config`, поэтому позже меняйте их в файле, затем `/reload-plugins` и `/cg-encrypt on`. Чужие данные компьютер читает любым способом, который умеет открывать сам: SQLCipher только при установленном `sqlcipher3`.
- **Скорость.** На зашифрованном индексе `recall` медленнее примерно на 0,08 с (замер 2026-10-27, 24,7 тыс. векторов). Разница растёт вместе с числом векторов. Замер 2026-11-02 на копии настоящего индекса (25,3 тыс. векторов, медиана 20 запусков): один поиск занимает 290 мс с SQLCipher и 170 мс с EFS, в обоих случаях страницы 16 КБ.
- **Что принимается вместе с EFS:**
  - Копия индекса на флешку FAT или exFAT и в сеть получается открытой, как и копия программой, которая читает файл и пишет его заново. Сам мод индекс наружу не копирует.
  - Файлы открываются только под той же учётной записью Windows. Если индекс под EFS не открывается (другой пользователь, утерян сертификат), мод скажет об этом и новый пустой индекс поверх не создаст.
  - Если переустановить Windows без резервной копии сертификата, прежний индекс не открыть. Удалите его, и мод соберёт новый из разговоров на диске. Копия сертификата по желанию, мод её не делает. Чтобы сделать её, выполните `cipher /x <файл>`: Windows спросит пароль и сохранит сертификат EFS и ключ в файл `.pfx`, защищённый этим паролем.
  - Файл, который держит открытым чат или фоновая задача, EFS не зашифрует: команда скажет, что файлы заняты. Повторите её через минуту.
- **Остаётся открытым:**
  - разговоры Claude Code, `%USERPROFILE%\.claude\projects\*.jsonl`;
  - файлы автопамяти каждого проекта на локальном диске (`.md`): их читает Claude Code;
  - передачи дел, папка `handoffs` рядом с индексом: тот же текст уходит в чат открытым. С EFS сами файлы на диске зашифрованы.
  - `forgotten.json` в `%USERPROFILE%\.claude\cacheguard`, его создают только для индекса в другой папке: ключи записей, удалённых через `forget`. Это хеши, текста в них нет.

## Индекс в другой папке

Для компьютера, где на C: мало места. Индекс растёт с каждым чатом, и его можно перенести на другой локальный диск. Только Windows. Без этой команды ничего не меняется, индекс лежит в `%USERPROFILE%\.claude\cacheguard\`.

1. **Переехать:** `/cg-index-dir D:\CacheGuard`. Без пути откроется окно выбора папки.
   - Команда копирует индекс, сверяет копию и после этого переключает мод на новую папку. Если индекс занят чатом или фоновой задачей, она просит повторить через минуту.
   - Затем окно спрашивает, удалить ли старую копию. По умолчанию «Нет». Старые файлы удаляются только после «Да». После «Нет» они остаются, а `/cg-health` напоминает, где они лежат. Чтобы спросить снова, повторите `/cg-index-dir` с той же папкой.
2. **Проверить:** `/cg-health`. В строке «Индекс» теперь новый путь, например `D:\CacheGuard\index.db`.

Фоновая задача и инструменты `recall` и `lesson_save` сами работают с новой папкой. Ничего переустанавливать не нужно.

Что ещё нужно знать:
- **Что переезжает:** `index.db`, его резервная копия `index.before-stage2.db` (если есть), папка `handoffs` и `job.xml` фоновой задачи. Зашифрованный индекс переезжает зашифрованным. Индекс под EFS остаётся под EFS: целевая папка шифруется до копирования.
- **Что остаётся на C:** файл `settings.json` (в нём ключ шифрования и новая строка `indexDir`) и разговоры Claude Code, `%USERPROFILE%\.claude\projects`.
- **Отказ.** Команда ничего не меняет и называет причину, если:
  - папка не на локальном несъёмном диске (сетевые пути, сетевые и съёмные диски не подходят) или лежит внутри OneDrive
  - в папке уже есть другой `index.db`, чужую базу команда не перезаписывает
  - на целевом диске не хватает места, нужен размер файлов индекса и ещё 200 МБ
  - рядом с индексом лежит `index.db.plain`, сначала доведите до конца `/cg-encrypt on`
  - индекс под EFS, а диск папки не умеет шифровать файлы (нужен NTFS): выберите папку на диске NTFS или сначала выключите шифрование (`/cg-encrypt off`)
  - на C: ещё не слиты записи за время, пока папки не было (см. ниже).
- **Если папки или `index.db` в ней не стало** (диск отключили, папку удалили), мод говорит об этом уведомлением, один раз за сессию, и строкой в `/cg-health`: «индекс в D:\CacheGuard недоступен, сейчас работаю с …». Он работает с индексом на C:, а `indexDir` не меняет.
  - Если в стандартной папке уже лежит индекс (старая копия после «Нет»), работа идёт с ним. Если нет, новый создаётся только когда на C: свободно не меньше 2 ГБ. Иначе команды, которым нужен индекс, отвечают ошибкой с путями и цифрами, и ничего не создаётся. Команды без индекса работают: передача дел кнопки «Новый работник», подсчёт токенов и предпросмотр сжатия. Пока так, в строке состояния стоит «Индекс недоступен, подробности в /cg-health», а на каждое ваше сообщение приходит уведомление с причиной.
  - Синхронизация идёт как обычно.
  - Удалённое через `forget` остаётся удалённым и на C:. Его ключи лежат в `forgotten.json` рядом с `settings.json`, и индекс на C: применяет их раньше, чем прочитает хоть один разговор.
- **Когда папка вернулась**, первый же запуск `cg.py` (фоновая задача или команда в чате) сам вливает в неё всё, что накопилось на C:, и удаляет временный индекс. Без вопроса, место на C: дороже. Старая копия, которую вы оставили ответом «Нет» и которая заменяла индекс на время сбоя, вливается и удаляется так же. Сообщение называет число влитых записей, и `/cg-health` его хранит. Удалённое через `forget` не возвращается. Если слияние не сошлось, оба индекса остаются на месте, работа идёт с папкой индекса, `/cg-health` показывает причину, а следующий запуск пробует снова.
- **Папка не вернётся.** Пока мод работает с C:, команда с полным путём стандартной папки, `/cg-index-dir C:\Users\<имя>\.claude\cacheguard`, убирает `indexDir` и ничего не копирует. C: становится постоянным местом индекса. Если папка вернулась, а индекса в ней нет, команда с путём этой папки переносит индекс с C: в неё.
- **Вернуть индекс на C:** из рабочей папки его переносит та же команда, `/cg-index-dir C:\Users\<имя>\.claude\cacheguard`. Если на C: осталась старая копия, не совпадающая с индексом байт в байт, команда откажет. Тогда сначала повторите `/cg-index-dir` с рабочей папкой и ответьте «Да» на вопрос об удалении. Копия, совпадающая байт в байт, переезд не останавливает.
- **Слияние не получается раз за разом.** `/cg-health` показывает причину в своей строке, а `/cg-index-dir` отказывает, пока слияние не сделано. Если причина повторяется каждый раз, удалите `index.db` в `C:\Users\<имя>\.claude\cacheguard` вручную, но только когда сохранённые там записи уже не нужны. Индекс в рабочей папке остаётся как есть.

## Полезно знать

- **Мод читается прямо из папки репозитория.** Держите её на ветке `master`. Если раньше была `stage1`, один раз выполните `git checkout master; git pull`. После `git pull` наберите в Claude Code `/reload-plugins`, переустанавливать не нужно.
- **Индекс и векторы** лежат в `%USERPROFILE%\.claude\cacheguard\index.db`, в репозиторий не попадают. Каждый компьютер ведёт свою базу; общая папка синхронизации — только обмен пачками между ними.
- **Если индекс переехал** командой `/cg-index-dir`, он лежит в выбранной папке (см. «Индекс в другой папке»).
- **`/cg-index rebuild`** перечитывает все транскрипты и добавляет только недостающее: векторы остаются, ничего не удаляется.
- **Настройки:** свой файл `%USERPROFILE%\.claude\cacheguard\settings.json`, по одному на компьютер. Он остаётся в этой папке, даже когда индекс переехал. Ключи: `language`, `compression`, `syncDir`, `bandMinTokens` и `bandIdleMinutes` (пороги полосы), `showLimits` (строка лимитов), `python` (команда Python, если это `py`, а не `python`), `embedModel`, `lessons` и `lessonsMinScore` (уроки), `indexCipher` (шифрование индекса), `shareCipher` (шифрование папки синхронизации), `indexDir` (папка индекса). Таблица со значениями по умолчанию лежит в [README.ru.md](README.ru.md).
  - Мод создаёт файл при первом запуске со всеми текущими значениями, остаётся открыть и поправить. В файле можно оставить только те ключи, которые вы меняете.
  - Мод читает файл при каждой загрузке: в начале чата и по `/reload-plugins`. После правки наберите `/reload-plugins`.
  - Значения из файла главнее `/config`. В десктопном приложении у модов нет окна настроек, поэтому настройки лежат в файле. `/config` в терминальном `claude` по-прежнему работает, но при расхождении побеждает файл.
  - Обратные слеши в JSON удваиваются: `"Z:\\cacheguard"`.
  - `/cg-health` показывает строку с путём к файлу.
  - Строку `encryptionKey` пишет сам мод: это ключ шифрования под защитой Windows. Не правьте её.
  - Строку `indexDir` пишет команда `/cg-index-dir`. Руками её не правят: файлы индекса сами не переедут.
  - Если файл испорчен (неверный JSON), мод покажет уведомление с именем файла и оставит значения из `/config`. Неизвестный ключ или значение не того типа даёт такое же уведомление, а этот ключ пропускается.
- **Полоса над полем ввода** — одна область на все моды. Полоса CacheGuard рисуется в своей рамке с заголовком, а полосы других модов остаются под ней.
- **`/cg-stats`** пишет замеры в Obsidian через MCP-сервер `obsidian`. Он должен быть подключён на этом компьютере. Если Obsidian недоступен, замер ждёт в очереди и уходит при следующем запуске.
