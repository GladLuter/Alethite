# Встановлення Alethite у Windows

Цей файл про встановлення, налаштування, оновлення й видалення плагіна Alethite. Що плагін робить, написано в [README.uk.md](README.uk.md).

Кроки 1-6 з розділу «Встановлення» проходять швидко: найдовше будується індекс, кілька хвилин. Крок 7 (вектори) йде годинами й може зачекати. Усе, що в розділах «Необов'язкові можливості» та «Лише якщо ви користувалися старішою збіркою», можна пропустити.

## Що потрібно заздалегідь

- **Десктопний застосунок Claude Code**, версія не нижче 2.1.295 (версія рушія). Перевірка:
  ```powershell
  Get-ChildItem "$env:USERPROFILE\.claude\projects" -Recurse -Filter *.jsonl | Sort-Object LastWriteTime | Select-Object -Last 1 | Get-Content -Tail 50 | Select-String '"version":"([^"]+)"' | Select-Object -Last 1 | ForEach-Object { $_.Matches[0].Groups[1].Value }
  ```
  Команда друкує номер на кшталт `2.1.300`. Якщо вона нічого не друкує, чатів у вас ще немає: відкрийте будь-який чат, надішліть одне повідомлення й запустіть команду знову.
- **Python 3.8 або новіший і numpy.**
  - Перевірка: `python --version` друкує номер версії, а `python -c "import numpy; print(numpy.__version__)"` друкує версію numpy.
  - Python немає: встановіть його з python.org і позначте «Add python.exe to PATH».
  - Якщо numpy немає: `python -m pip install numpy`. Запускайте у звичайному вікні PowerShell, яке ви відкрили самі, а не в чаті Claude. `pip` з Claude Desktop (збірка з Microsoft Store) ставить пакети у свою пісочницю, і звичайний Python їх не бачить.
- **Ollama з моделлю ембедингів**, для пошуку за змістом. Не обов'язково: без неї пошук іде самими словами, а додати її можна пізніше. Якщо Ollama ще немає, встановіть її з ollama.com. Після встановлення вона працює в треї. Потім:
  ```powershell
  ollama pull embeddinggemma
  ```
  Це близько 622 МБ. Команда закінчується словом `success`.
- **git.**

## Встановлення

1. **Завантажити код** (гілка `master`):
   ```powershell
   git clone https://github.com/GladLuter/Alethite.git C:\_git\Alethite
   ```
   Цю папку залиште. Плагін читається безпосередньо з неї, тому не переносьте й не видаляйте її.
2. **Знайти рушій десктопа.** `claude` з PATH це окремий CLI, часто старіший, тому потрібен саме `claude.exe` десктопа. Береться найновіший файл:
   ```powershell
   $CC = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe", "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Команда має надрукувати шлях, що закінчується на `claude.exe`. Порожній рядок означає, що нічого не знайшлося. Перший шаблон для сучасних збірок десктопа, два інші для старіших. Якщо нічого не знайшлося, шукайте ширше (це повільно й може тривати кілька хвилин):
   ```powershell
   $CC = (Get-ChildItem $env:LOCALAPPDATA, $env:APPDATA -Recurse -Filter claude.exe -ErrorAction SilentlyContinue | Where-Object FullName -like '*claude-code*' | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Не закривайте це вікно PowerShell, доки не закінчите крок 3: у новому вікні `$CC` порожня.
3. **Встановити плагін:**
   ```powershell
   & $CC plugin marketplace add C:\_git\Alethite
   & $CC plugin install alethite@alethite
   ```
   Кожна команда друкує коротке підтвердження. Помилка тут зазвичай означає, що `$CC` порожня: повторіть крок 2. Потім повністю закрийте десктопний застосунок (разом зі значком у треї, якщо він там є) і відкрийте його знову.
4. **Зібрати індекс** розмов цього комп'ютера (це запис ваших старих чатів, за яким іде пошук). Першого разу це триває кілька хвилин:
   ```powershell
   python C:\_git\Alethite\plugin\scripts\cg.py index
   ```
   Наприкінці команда друкує один рядок JSON з результатом.
   - Якщо ви працюєте на двох комп'ютерах, на цьому вже налаштовано синхронізацію (розділ «Два комп'ютери: спільна пам'ять») і індекс новий, спершу виконайте там `cg.py sync`. Записи й вектори цього комп'ютера повернуться з його папки, і рахувати їх заново не доведеться. Інакше пропустіть.
5. **Мова.** Типово плагін говорить англійською: інтерфейс, тексти, які плагін дає Claude, і передача справ (коротке зведення старого чату, що потрапляє в новий). Спершу відкрийте новий чат: файл налаштувань створюється під час першого запуску. Відкрийте його командою `notepad $env:USERPROFILE\.claude\alethite\settings.json`, поставте в ньому `"language": "uk"` і наберіть у полі чату `/reload-plugins`. Для російської поставте `"ru"`. Параметр `--lang ru` або `--lang uk` перед `index` задає мову повідомлень і помилок скриптів у терміналі. Без нього вони англійською.
6. **Перевірити:** у новому чаті наберіть `/al-health` у полі чату Claude Code (усі команди `/al-...` набираються там). Там мають бути версія, індекс, папка автопам'яті, проєкт, вектори «N з M» і рядок синхронізації. «Вектори 0 з N» нормально, поки ви не зробили крок 7. Рядок із помилкою означає, що один із кроків вище не спрацював.
7. **Порахувати вектори.** Не обов'язково й повільно: це години. Вектори дають пошуку змогу знаходити розмови за змістом. Цей крок можна пропустити зараз і запустити пізніше чи на ніч. Потрібна Ollama з моделлю з розділу «Що потрібно заздалегідь». На процесорі Intel початкового рівня близько 25 тисяч шматків історії зайняли приблизно 6 годин. Після зупинки розрахунок продовжується з того самого місця:
   ```powershell
   python C:\_git\Alethite\plugin\scripts\cg.py embed --max-seconds 100000
   ```
   `--max-seconds 100000` це стеля близько 28 годин. Команда зупиняється раніше, коли всі вектори пораховано. Далі нові записи дораховуються самі на старті сесії, до 2 хвилин за раз.
   - **Ноутбук:** на час розрахунку не давайте йому заснути. На зарядці він засинає без введення й зупиняє розрахунок. Після пробудження запустіть команду знову.
   - **Вбудована відеокарта Intel (Iris Xe):** на ній розрахунок іде приблизно вдвічі швидше. Див. «Корисно знати».

## Оновлення

Плагін читається безпосередньо з папки клону, тому оновлення це `git pull`.

1. Тримайте клон на гілці `master`. У клоні:
   ```powershell
   cd C:\_git\Alethite
   git pull
   ```
2. Наберіть `/reload-plugins` у кожному відкритому чаті.
3. Перевірте: наберіть `/al-health`.

## Видалення Alethite

1. Якщо фонове завдання ввімкнене, вимкніть його в чаті: `/al-job off`.
2. Приберіть плагін і його маркетплейс. У новому вікні PowerShell `$CC` порожня, тому спершу виконайте команду з розділу «Встановлення», крок 2. Потім:
   ```powershell
   & $CC plugin uninstall alethite@alethite
   & $CC plugin marketplace remove alethite
   ```
   Після цього перезапустіть десктопний застосунок.
3. Якщо хочете прибрати й дані, видаліть вручну:
   - `%USERPROFILE%\.claude\alethite`: індекс, `settings.json` з ключем шифрування, передачі справ.
   - Папку індексу, якщо ви переносили її командою `/al-index-dir`.
   - Підпапку цього комп'ютера в папці синхронізації (`<папка>\<ім'я комп'ютера>`), якщо ви користувалися синхронізацією.
   - Клон.

   Розмови самого Claude Code (`%USERPROFILE%\.claude\projects`) і файли автопам'яті лишаються недоторканими.

## Корисно знати

- **Індекс і вектори** лежать у `%USERPROFILE%\.claude\alethite\index.db` і в репозиторій не потрапляють. Кожен комп'ютер веде свій індекс. Спільна папка синхронізації лише носить пачки між ними.
- **Якщо індекс переїхав** командою `/al-index-dir`, він лежить у вибраній папці (див. «Індекс в іншій папці»).
- **`/al-index rebuild`** перечитує всі транскрипти й додає лише те, чого бракує: вектори лишаються, нічого не видаляється.
- **Налаштування:** окремий файл `%USERPROFILE%\.claude\alethite\settings.json`, по одному на комп'ютер. Він лишається в цій папці, навіть коли індекс переїхав. Ключі та їхні типові значення перелічено в таблиці налаштувань у [README.uk.md](README.uk.md).
  - Плагін створює файл під час першого запуску з усіма поточними значеннями. Його достатньо відкрити й поправити. У файлі можна лишити тільки ті ключі, які ви змінюєте.
  - Плагін читає файл під час кожного завантаження: на початку чату й за `/reload-plugins`. Після правки наберіть `/reload-plugins`.
  - Значення з файлу мають пріоритет над `/config`. У десктопному застосунку для плагінів немає вікна налаштувань, тому налаштування лежать у файлі. `/config` у терміналі `claude` і далі працює, але за розбіжності перемагає файл.
  - Зворотні скісні риски в JSON подвоюються: `"Z:\\alethite"`.
  - `/al-health` показує рядок зі шляхом до файлу.
  - Рядок `encryptionKey` пише сам плагін: це ключ шифрування під захистом Windows. Не правте його.
  - Рядок `indexDir` пише команда `/al-index-dir`. Руками його не правте: файли індексу самі не переїдуть.
  - Рядок `projectAliases` пишете ви, коли папку проєкту перейменували чи перенесли: `"projectAliases": {"C:\\work\\new": ["C:\\work\\old"]}`. Нова папка тоді знаходить розмови й уроки старої під час пошуку. Нові розмови й уроки зберігаються під новою папкою. В індексі нічого не переписується, у папку синхронізації нічого не йде, тому на кожному комп'ютері свої псевдоніми. Плагін читає файл під час кожного виклику. `/reload-plugins` не потрібен. `/config` цей ключ не показує.
  - Якщо файл зіпсований (хибний JSON), плагін покаже сповіщення з іменем файлу й залишить значення з `/config`. Невідомий ключ або значення не того типу дає таке саме сповіщення, а цей ключ пропускається.
- **Смуга над полем вводу** це одна область для всіх плагінів. Рядок Alethite іде без рамки, «Деталі» відкриваються в рамці із заголовком, а смуги інших плагінів лишаються під ним.
- **Кнопка «Після скидання»** з'являється після натискання «Новий працівник», якщо якийсь ліміт використано на 90% або більше. Вона чекає скидання ліміту, лише поки застосунок відкритий. Якщо його закрили, працівник запуститься, коли ви відкриєте цей чат після скидання. Модель лишається поточною.
- **Скільки заощаджено** рахується за транскриптами цього комп'ютера. Модель при цьому не викликається.
- **`/al-stats` потребує Obsidian.** Якщо ви ним не користуєтеся, цю команду пропустіть. Вона пише через MCP-сервер з назвою `obsidian`, який має інструменти `list_vault_files`, `get_note_properties` і `create_vault_file`. Сервер має бути підключений на цьому комп'ютері.
  - Нотатки йдуть у папку сховища, названу мовою мода. Англійською це `Alethite/Measurements` і зведення `Summary.md`, російською `Alethite/Замеры` і `Сводка.md`, українською `Alethite/Заміри` і `Зведення.md`. Якщо змінити мову, нові нотатки підуть у нову папку, а старі лишаться де були.
  - Якщо Obsidian недоступний, замір чекає в черзі й іде під час наступного запуску.
  - Усе інше в плагіні працює без Obsidian.
- **Вектори швидше на вбудованій відеокарті Intel (Iris Xe).** Разовий розрахунок (розділ «Встановлення», крок 7) іде на ній приблизно вдвічі швидше, а вектори виходять ті самі (замір 2026-10-19 на ноутбуці: 2,44 довгих шматки на секунду проти 1,15 на процесорі). Ollama бачить таку карту, лише якщо її запустити з `OLLAMA_IGPU_ENABLE=1`. Для цього зупиніть звичайну Ollama в треї, потім у вікні PowerShell:
  ```powershell
  $env:OLLAMA_IGPU_ENABLE = '1'; ollama serve
  ```
  В іншому вікні запустіть команду розрахунку векторів. Після нього закрийте це вікно й знову запустіть Ollama з меню «Пуск». Не залишайте цей режим увімкненим: текстові моделі на вбудованій карті повільніші.

## Необов'язкові можливості

Усе, що нижче, до розділу «Лише якщо ви користувалися старішою збіркою», не обов'язкове. Під час першого встановлення це можна пропустити.

### Фонове завдання

Завдання не обов'язкове. Воно підтримує індекс і вектори свіжими, поки жоден чат не відкритий.

Вмикайте його на кожному комп'ютері: у чаті `/al-job on` (або `/al-job on 15`, щоб раз на 15 хвилин).
- Воно додає в Планувальник завдань Windows завдання «Alethite». Там його можна побачити й видалити. Воно без вікна й працює, лише поки ви ввійшли в систему. На батареї вектори чекають, поки ноутбук підключать до живлення.
- Налаштування воно бере з того самого файлу `settings.json`, що й плагін.
- Воно запускає `cg.py` встановленого плагіна. Після оновлення плагіна завдання саме переводиться на нову копію на старті сесії.
- `/al-job` показує стан і останній запуск. `/al-job off` видаляє завдання.
- Якщо завдання не запускається, перевірте, що Python встановлено з python.org (поруч із `python.exe` має лежати `pythonw.exe`).

### Уроки

Уроки працюють самі. Claude зберігає зрозумілу помилку через `lesson_save`. `/al-lessons` показує уроки проєкту, `/al-lessons forget <pos>` видаляє один.
- Урок приходить до повідомлення, близького за змістом, і зупиняє команду, що містить його тригер.
- Щоб зберегти правило для всіх проєктів, попросіть Claude зберегти його для всіх проєктів. Такі правила приходять у кожен чат, тому коштують токенів скрізь. Скільки їх і чого вони коштують, видно в `/al-health`.
- Якщо уроки приходять не до речі, підніміть `lessonsMinScore` у `settings.json` до `0.55`. Якщо не приходять ніколи, опустіть до `0.4`. Щоб вимкнути: `"lessons": false`.
- Помилки інструментів із розмов індексуються від самого початку, тому `recall` їх знаходить. Після оновлення з версії без пошуку помилок один раз перебудуйте індекс, щоб у нього потрапили помилки інструментів зі старих розмов:
  ```powershell
  python C:\_git\Alethite\plugin\scripts\cg.py index --rebuild
  ```
  Перебудова лише додає відсутнє. Вектори для нових записів дорахує фонове завдання або наступний запуск чату.

### Два комп'ютери: спільна пам'ять

Це потрібно, лише якщо ви користуєтеся Alethite більш ніж на одному комп'ютері.

Кожен комп'ютер викладає свої нові розмови, вектори й факти автопам'яті в спільну папку й забирає звідти чужі. Викладає він пачками: пачка це одне викладання нових записів з одного комп'ютера.
- Пише він лише у свою підпапку (`<папка>\<ім'я комп'ютера>\`), тому індекс не псується, навіть якщо обидва комп'ютери працюють одночасно.
- Без мережевої папки все працює як раніше. Синхронізація наздоганяє, коли папка знову доступна.

1. **Створити папку** на мережевому диску, один раз, наприклад `\\NAS\share\alethite`. Сам плагін її не створює: якщо диск не підключено, він покаже помилку, а не почне писати на локальний диск.
2. **На кожному комп'ютері** вкажіть її у файлі налаштувань `%USERPROFILE%\.claude\alethite\settings.json`: `"syncDir": "\\\\NAS\\share\\alethite"`, потім `/reload-plugins`. Зворотні скісні риски в JSON подвоюються.
3. **Перший обмін.** Уся історія це десятки мегабайтів. Плагін синхронізує не довше 60 секунд за раз і продовжує під час наступного запуску, але першого разу зручніше з термінала. Виконайте команду на першому комп'ютері, потім на другому:
   ```powershell
   python C:\_git\Alethite\plugin\scripts\cg.py sync --sync-dir \\NAS\share\alethite --max-seconds 3600
   ```
   Потім ще раз на першому, щоб забрати історію другого. Вектори переїжджають разом із записами: перераховувати чужі не потрібно, якщо модель ембедингів на обох однакова.
4. **Далі автоматично:** на старті сесії, після індексу й векторів. Вручну: `/al-sync`. Відповідь каже, скільки викладено й влито, і показує помилки.
5. **Перевірити:** `recall` на другому комп'ютері знаходить розмову з першого, а `/al-health` показує обидва комп'ютери й номери їхніх останніх пачок.

Що ще треба знати:
- **Коротка пам'ять** синхронізується для проєкту поточного чату.
  - Факти, створені на цьому комп'ютері, ідуть у спільну папку.
  - Факти іншого комп'ютера копіюються в папку автопам'яті, якщо їх там немає, і до `MEMORY.md` додається рядок-покажчик.
  - Власний файл із тим самим ім'ям ніколи не перезаписується: чужа версія лягає поруч як `ім'я--КОМП'ЮТЕР.md`. Влитий факт, який ви видалили, не повернеться.
- **Проєкт** розпізнається за шляхом без домашньої папки: `C:\Users\Ann\work\x` і `C:\Users\alice\work\x` це один проєкт. Шляхи поза профілем (`C:\_git\…`) збігаються й так.

Виправлення, лише якщо щось зламалося:
- **Зіпсована пачка** (обрив мережі, збій диска) зупиняє прийом лише від її комп'ютера. Помилку видно в `/al-health` під час кожної синхронізації. Якщо пачку не відновити: `/al-sync skip <комп'ютер> <номер>`. Пропуск видно в `/al-health`.
- **Видалити запис** (наприклад, секрет, який фільтр пропустив) можна лише явно, і видалення дійде до іншого комп'ютера:
  ```powershell
  python C:\_git\Alethite\plugin\scripts\cg.py forget --conv <id розмови> --pos <pos>
  ```
  `conv` і `pos` беруться з рядка знахідки `recall`. Більше нічого з індексу не зникає: ні під час перебудови, ні коли Claude Code переписує чи видаляє транскрипти.

### Стиснення пам'яті

Плагін сам стискає те, що кладе в контекст моделі: видачу `recall` і `recall_more` та цитати розмови в передачі справ. Стиснення механічне, без викликів моделі. Код, шляхи, посилання, числа, імена й заперечення не чіпаються.

- **Рівень:** ключ `"compression"` у файлі налаштувань `%USERPROFILE%\.claude\alethite\settings.json`, потім `/reload-plugins`.
  - `off`: без стиснення.
  - `lite`: пробіли й розмітка.
  - `full`: плюс службові слова.
  - `ultra`: плюс пунктуація й великі літери (типово).
- **Подивитися, що робить рівень**, на будь-якому тексті:
  ```powershell
  python C:\_git\Alethite\plugin\scripts\cg.py compress --level ultra --file note.txt
  ```
- **Скільки пам'яті в контексті:** `/al-stats` пише у свою нотатку розділ «Пам'ять у контексті»: правило пам'яті, `MEMORY.md`, результати `recall` та їхня вартість, передачі справ. `/al-health` показує рівень стиснення й розмір `MEMORY.md`.
- Якщо Claude гірше розуміє стиснені уривки, поставте `full` або `lite`.

### Шифрування

За бажанням і лише у Windows. У Windows Pro, Enterprise або Education (редакцію показує Параметри, Система, Про систему) найпростіша пара: `efs` для індексу і `cryptography` для папки синхронізації, як у прикладі в кроці 1. Цій парі не потрібен додатковий пакет.

Два терміни. Пачка: одне викладання нових записів з одного комп'ютера. Покоління: повний набір підпапки комп'ютера в одному шифрі (`gen-0001`, `gen-0002` і так далі). Увімкнення чи вимкнення шифрування і зміна шифру починають нове.

Шифруються індекс (з його резервною копією `index.before-stage2.db`, якщо вона є) і все, що комп'ютер кладе в папку синхронізації. У папці можна прочитати ім'я комп'ютера, номери, кількість і розміри пачок. У мітці покоління (`gen-0001\generation.json`) ще й назву способу шифрування, відбиток ключа та дату. За відбитком ключ не дізнатися.
- Ключ лежить у `settings.json` під захистом Windows (DPAPI). На іншому комп'ютері або під іншим обліковим записом Windows цей файл ключа не дасть.
- Поки ви не набрали `/al-encrypt on`, у вас нічого не змінюється.

**Способи шифрування.** Індекс і папка синхронізації шифруються кожен своїм способом, і кожен комп'ютер обирає їх сам:
- Індекс, ключ `indexCipher`:
  - `sqlcipher` (типово): SQLCipher, потрібен пакет `sqlcipher3`.
  - `efs`: шифрування файлів самою Windows. Потрібні Windows Pro (або Enterprise, Education) і диск NTFS. Пакети ставити не треба. Під EFS іде вся папка плагіна `%USERPROFILE%\.claude\alethite` і папка індексу, якщо вона інша: індекс, журнал, резервні копії, передачі справ, `settings.json`, `forgotten.json`.
- Папка синхронізації, ключ `shareCipher`:
  - `sqlcipher` (типово): SQLCipher, потрібен пакет `sqlcipher3`.
  - `cryptography`: AES-GCM, вбудований у Windows (`bcrypt.dll`). Пакет `cryptography` більше не потрібен.
- **Smart App Control** може не дати завантажити `sqlcipher3`, бо його модуль не підписаний. Під ним годяться тільки `efs` і `cryptography`, а комп'ютеру з цією парою `sqlcipher3` не потрібен. Винятки: переведення вже наявного індексу SQLCipher і читання папки комп'ютера, який пише SQLCipher.
- Свою підпапку в папці синхронізації кожен комп'ютер пише своїм способом, а чужі читає за міткою покоління. Якщо чужу підпапку записано SQLCipher, а тут `sqlcipher3` не завантажується, `/al-health` називає той комп'ютер і радить перевести його на AES-GCM.

1. **Обрати способи** на кожному комп'ютері в `%USERPROFILE%\.claude\alethite\settings.json`. Наприклад, EFS і AES-GCM:
   ```json
   {
     "indexCipher": "efs",
     "shareCipher": "cryptography"
   }
   ```
   Якщо нічого не обирати, в обох лишається `sqlcipher`. `/al-encrypt on` і `join` беруть способи з цього файлу й записують їх назад поруч із ключем. Плагін читає файл під час завантаження, тому правте його до `/reload-plugins` у наступних кроках.
2. **Поставити пакет `sqlcipher3`**, лише якщо він потрібен: для способу `sqlcipher` (індексу чи папки) і один раз для переведення вже зашифрованого індексу SQLCipher в EFS. Ставте на кожному комп'ютері зі звичайного вікна PowerShell, не зсередини Claude. `pip` з Claude кладе пакети у свою пісочницю, і фонове завдання їх не побачить.
   ```powershell
   python -m pip install sqlcipher3
   ```
3. **Перший комп'ютер:** `/reload-plugins`, потім `/al-encrypt on`. Вікна «Alethite» можуть опинитися за іншими вікнами.
   - З `efs` команда спершу перевіряє, що диск уміє EFS. Якщо ні (Windows Home або диск не NTFS), вона відмовить до створення ключа, нічого не змінивши.
   - З `efs` індексу потрібна й власна папка. EFS зашифрував би все, що в ній лежить, тому якщо папка індексу не збігається з папкою плагіна і в ній є чужі файли, команда відмовить до створення ключа. Перенесіть індекс в окрему папку командою `/al-index-dir` і повторіть.
   - У першому вікні буде **код відновлення**. Він показується один раз. Ctrl+C копіює текст вікна: вставте код у менеджер паролів. Без нього зашифровану історію не прочитати, якщо зникнуть комп'ютери або їхні облікові записи Windows.
   - Питання «Код відновлення збережено?»: типово «Ні». Шифрування почнеться лише після «Так».
   - Індекс і його резервна копія шифруються. З `sqlcipher` відкриті копії (`index.db.plain`) видаляються лише після «Так». Після «Ні» вони лишаються, і `/al-encrypt on` запитає знову.
   - З `efs` папка плагіна і папка індексу йдуть під шифрування Windows, а індекс SQLCipher стає звичайною базою під EFS зі сторінками 16 КБ. Відкритої копії поза EFS не буває, тому питання про `index.db.plain` немає.
   - Папка синхронізації: комп'ютер викладає свою підпапку заново, обраним способом. Колишні дані в ній (відкриті або іншим способом) видаляються лише після «Так» і лише коли нові викладено повністю.
4. **Другий комп'ютер:** `git pull`, свої способи в `settings.json` (крок 1), `/reload-plugins`, `/al-encrypt join`. Код відновлення вводиться у вікні зі схованим вводом. Ключ один на всі комп'ютери, тому `on` на другому відмовить і підкаже `join`.
   - Якщо на першому комп'ютері ви змінюєте спосіб папки (наприклад, SQLCipher на AES-GCM), приєднуйте другий лише після цього. Інакше він побачить покоління SQLCipher, яке під Smart App Control не відкриє.
5. **Перевірити:** `/al-health` на обох комп'ютерах пише, наприклад, «Шифрування: ввімкнено (індекс: EFS, папка синхронізації: AES-GCM)». Якщо щось не доведено до кінця, рядки під нею скажуть, що повторити. Лише стан показує `/al-encrypt status`.

Що ще треба знати:
- **Команди:** `/al-encrypt on | join | off | status`. Без аргумента виконується `status`.
  - `off` розшифровує індекс (з EFS знімає шифрування Windows з обох папок), викладає підпапку цього комп'ютера відкритою й прибирає ключ із `settings.json`. Вимикати треба на кожному комп'ютері. Новий `on` створює новий ключ, решта комп'ютерів приєднуються заново.
  - Втратили ключ (інший обліковий запис Windows, перевстановлення): `/al-encrypt join` з кодом відновлення.
  - Втратили і ключ, і код: цей комп'ютер своє зашифроване вже не прочитає. Вимкніть шифрування (`off`) на решті комп'ютерів і вручну видаліть папку цього комп'ютера в папці синхронізації, а якщо на ньому лишився зашифрований `index.db`, то й його (плагін збере новий з розмов на диску). Потім увімкніть шифрування заново: `on` на одному комп'ютері, `join` з новим кодом на решті.
- **Поки другий комп'ютер не приєднався**, перший нічого від нього не бере, а `/al-health` називає його: «виконайте на ньому `join`». Історія другого не губиться: після `join` він викладе її зашифрованою.
- **Межа часу.** Один запуск обмежений приблизно 10 хвилинами (межа десктопного застосунку). Велике перше викладання може не вкластися, і відповідь скаже, що не закінчено. Повторіть `/al-encrypt on` (або `join`): команда продовжить з того місця, де зупинилася. Будь-який крок можна безпечно повторити. Решту викладе й фонове завдання, але колишні відкриті дані з папки видалить лише повтор команди, після «Так».
- **Способи шифрування** задають ключі `indexCipher` (`sqlcipher` типово або `efs`) і `shareCipher` (`sqlcipher` типово або `cryptography`, тобто AES-GCM) у `settings.json`. `/al-encrypt on` і `join` самі записують їх у файл, а файл має пріоритет над `/config`. Змінюйте їх згодом у файлі, потім `/reload-plugins` і `/al-encrypt on`. Чужі дані комп'ютер читає будь-яким способом, який уміє відкривати сам: SQLCipher лише за встановленого `sqlcipher3`.
- **Швидкість.** На зашифрованому індексі `recall` повільніший приблизно на 0,08 с (24,7 тис. векторів), і різниця росте разом із кількістю векторів. Один пошук по 25,3 тис. векторів займає 290 мс із SQLCipher і 170 мс з EFS.
- **Що приймається разом з EFS:**
  - Копія індексу на флешку FAT чи exFAT, у мережу або програмою, що читає файл і пише його заново поза EFS, виходить відкритою. Сам плагін індекс назовні не копіює.
  - Файли відкриваються лише під тим самим обліковим записом Windows. Якщо індекс під EFS не відкривається, плагін скаже про це й новий порожній індекс поверх не створить.
  - Після перевстановлення Windows без копії сертифіката EFS старий індекс не відкрити: видаліть його, і плагін збере новий з розмов на диску. Копія сертифіката за бажанням, плагін її не робить. Щоб зробити її, виконайте `cipher /x <файл>`: Windows запитає пароль і збереже сертифікат EFS та ключ у файл `.pfx`, захищений цим паролем.
- **Що лишається відкритим:**
  - Розмови Claude Code, `%USERPROFILE%\.claude\projects\*.jsonl`.
  - Файли автопам'яті кожного проєкту на локальному диску (`.md`): їх читає Claude Code.
  - Передачі справ, папка `handoffs` поруч із індексом: той самий текст іде в чат відкритим. З EFS самі файли на диску зашифровані.
  - `forgotten.json` у `%USERPROFILE%\.claude\alethite`, його створюють лише для індексу в іншій папці: ключі записів, видалених через `forget`. Це хеші, тексту в них немає.

### Індекс в іншій папці

Для комп'ютера, де на C: мало місця. Індекс росте з кожним чатом, і його можна перенести на інший локальний диск. Лише Windows. Без цієї команди нічого не змінюється, індекс лежить у `%USERPROFILE%\.claude\alethite\`.

1. **Переїхати:** `/al-index-dir D:\Alethite`. Без шляху відкриється вікно вибору папки.
   - Команда копіює індекс, звіряє копію і лише після цього перемикає плагін на нову папку. Якщо індекс зайнятий чатом або фоновим завданням, вона просить повторити за хвилину.
   - Потім вікно питає, чи видалити стару копію. Типово «Ні». Старі файли видаляються лише після «Так». Після «Ні» вони лишаються, а `/al-health` нагадує, де вони лежать. Щоб запитати знову, повторіть `/al-index-dir` з тією самою папкою.
2. **Перевірити:** `/al-health`. У рядку «Індекс» тепер новий шлях, наприклад `D:\Alethite\index.db`.

Фонове завдання та інструменти `recall` і `lesson_save` самі працюють з новою папкою. Нічого перевстановлювати не треба.

Що ще треба знати:
- **Що переїжджає:** `index.db`, його резервна копія `index.before-stage2.db` (якщо є), папка `handoffs` і `job.xml` фонового завдання. Зашифрований індекс переїжджає зашифрованим. Індекс під EFS лишається під EFS: цільова папка шифрується до копіювання.
- **Що лишається на C:** файл `settings.json` (у ньому ключ шифрування і новий рядок `indexDir`) та розмови Claude Code, `%USERPROFILE%\.claude\projects`.
- **Відмова.** Команда нічого не змінює і називає причину, якщо:
  - папка не на локальному незнімному диску (мережеві шляхи, мережеві та знімні диски не підходять) або лежить усередині OneDrive
  - у папці вже є інший `index.db`, чужу базу команда не перезаписує
  - на цільовому диску не вистачає місця (потрібен розмір файлів індексу і ще 200 МБ)
  - поруч із індексом лежить `index.db.plain`, спершу доведіть до кінця `/al-encrypt on`
  - індекс під EFS, а диск папки не вміє шифрувати файли (потрібен NTFS): оберіть папку на диску NTFS або спершу вимкніть шифрування (`/al-encrypt off`)
  - на C: ще не злито записи за час, поки папки не було (див. нижче).
- **Якщо папки або `index.db` у ній не стало** (диск відключили, папку видалили), плагін каже про це сповіщенням, один раз за сесію, і рядком у `/al-health`: «індекс у D:\Alethite недоступний, зараз працюю з …». Він працює з індексом на C:, а `indexDir` не змінює.
  - Якщо у стандартній папці вже лежить індекс (стара копія після «Ні»), робота йде з ним. Якщо ні, новий створюється лише коли на C: вільно щонайменше 2 ГБ. Інакше команди, яким потрібен індекс, відповідають помилкою зі шляхами й цифрами, і нічого не створюється. Команди без індексу працюють: передача справ кнопки «Новий працівник», підрахунок токенів і попередній перегляд стиснення. Поки так, у рядку стану стоїть «Індекс недоступний, подробиці в /al-health», а на кожне ваше повідомлення приходить сповіщення з причиною.
  - Синхронізація йде як і раніше.
  - Видалене через `forget` лишається видаленим і на C:. Його ключі лежать у `forgotten.json` поруч із `settings.json`, і індекс на C: застосовує їх раніше, ніж прочитає хоч одну розмову.
- **Коли папка повернулась**, перший же запуск `cg.py` (фонове завдання або команда в чаті) сам вливає в неї все, що назбиралося на C:, і видаляє тимчасовий індекс. Без питання, бо місце на C: дорожче. Стара копія, яку ви залишили відповіддю «Ні» і яка замінювала індекс на час збою, вливається й видаляється так само. Повідомлення називає кількість влитих записів, і `/al-health` її зберігає. Видалене через `forget` не повертається. Якщо злиття не зійшлося, обидва індекси лишаються на місці, робота йде з папкою індексу, `/al-health` показує причину, а наступний запуск пробує знову.
- **Папка не повернеться.** Поки плагін працює з C:, команда з повним шляхом стандартної папки, `/al-index-dir C:\Users\<ім'я>\.claude\alethite`, прибирає `indexDir` і нічого не копіює. C: стає постійним місцем індексу. Якщо папка повернулась, а індексу в ній немає, команда зі шляхом цієї папки переносить індекс з C: у неї.
- **Повернути індекс на C:** з робочої папки його переносить та сама команда, `/al-index-dir C:\Users\<ім'я>\.claude\alethite`. Якщо на C: лишилась стара копія, що не збігається з індексом байт у байт, команда відмовить. Тоді спершу повторіть `/al-index-dir` з робочою папкою і дайте відповідь «Так» на питання про видалення. Копія, що збігається байт у байт, переїзд не зупиняє.
- **Злиття не виходить раз за разом.** `/al-health` показує причину у своєму рядку, а `/al-index-dir` відмовляє, поки злиття не зроблено. Якщо причина повторюється щоразу, видаліть `index.db` у `C:\Users\<ім'я>\.claude\alethite` вручну, але лише коли збережені там записи вже не потрібні. Індекс у робочій папці лишається як є.

## Лише якщо ви користувалися старішою збіркою

Новим користувачам цей розділ не потрібен.

### З alethite@alethite-local

Для встановлень, зроблених до перейменування маркетплейса. Ідентифікатор плагіна тепер `alethite@alethite`, а маркетплейс називається `alethite`.

1. Задайте `$CC` (у новому вікні PowerShell вона порожня):
   ```powershell
   $CC = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe", "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Якщо нічого не знайшлося, скористайтеся ширшим пошуком у розділі «Встановлення», крок 2.
2. Приберіть стару реєстрацію й зробіть нову:
   ```powershell
   & $CC plugin uninstall alethite@alethite-local
   & $CC plugin marketplace remove alethite-local
   & $CC plugin marketplace add C:\_git\Alethite
   & $CC plugin install alethite@alethite
   ```
3. Наберіть `/reload-plugins` у кожному відкритому чаті, потім `/al-health`.

Папка з даними і `settings.json` лишаються на місці. Значення, які ви задали через `/config` під старим ідентифікатором, не переносяться. Перевірте їх у плагіні й задайте знову те, що ще потрібно.

### З CacheGuard

Плагін раніше називався Claude-CacheGuard, так само називався й репозиторій. Це була попередня приватна збірка. Комп'ютер зі старим плагіном переводиться за кроками нижче. Порядок важливий.

0. **Надіслати заміри, що чекають.** У чаті один раз наберіть `/cg-stats`. Нотатки із замірами, яких Obsidian ще не прийняв, лежать у сховищі старого плагіна і зникнуть разом із ним.
1. **Прибрати старий плагін.** У новому вікні PowerShell `$CC` порожня. Задайте її, як у розділі «Встановлення», крок 2 (якщо шлях не знайшовся, там же ширший пошук), і приберіть старий плагін:
   ```powershell
   $CC = (Get-ChildItem "$env:LOCALAPPDATA\Claude-Data\claude_*\claude-code\*\*\claude.exe", "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   & $CC plugin uninstall cacheguard@cacheguard-local
   & $CC plugin marketplace remove cacheguard-local
   ```
2. **Поставити новий.** Якщо клону в `C:\_git\Alethite` ще немає, спершу склонуйте його (розділ «Встановлення», крок 1). Потім:
   ```powershell
   & $CC plugin marketplace add C:\_git\Alethite
   & $CC plugin install alethite@alethite
   ```
3. **Перезавантажити.** Наберіть `/reload-plugins` у кожному відкритому чаті. Чат без перезавантаження працюватиме далі зі старим плагіном і може знову створити стару папку.
4. **Перевірити.** Наберіть `/al-health`. Перший виклик переносить папку плагіна `%USERPROFILE%\.claude\cacheguard` у `%USERPROFILE%\.claude\alethite`, а разом із нею індекс, ключ, налаштування й передачі справ. Якщо фонове завдання було ввімкнене, старе завдання Планувальника «CacheGuard» видаляється, а завдання «Alethite» створюється з тим самим інтервалом. У відповіді подивіться індекс, ключ, синхронізацію й завдання.
   - Якщо папку перенести не вийшло, відповідь назве причину. Плагін поки працює в старій папці, а наступний запуск спробує знову.
   - Якщо стара папка лишилась поруч із новою, її знову створив чат зі старим плагіном. Нічого не перенесено. Перевірте стару папку й видаліть її.
   - Індекс, який ви переносили командою `/al-index-dir`, лишається на місці. Переїжджає тільки папка плагіна.
   - Папка синхронізації продовжує працювати під старою назвою. Шлях у `syncDir` ви задали самі, перейменування його не торкається, папку на диску перейменовувати не треба.
5. **Зберегти пам'ять колишньої папки проєкту.** Клон тепер лежить в іншій папці, і пошук із неї не знайде старі розмови проєкту. Додайте в `%USERPROFILE%\.claude\alethite\settings.json` цей рядок:
   ```json
   "projectAliases": { "C:\\_git\\Alethite": ["C:\\_git\\Claude-CacheGuard"] }
   ```
   Вставте його всередину зовнішніх фігурних дужок файлу, а після попереднього рядка поставте кому. Файл цілком не замінюйте: у ньому ваші інші налаштування і, якщо шифрування ввімкнене, ключ шифрування. Плагін читає файл під час кожного виклику. Потім перевірте, що `recall` у чаті, відкритому в `C:\_git\Alethite`, знаходить старі розмови проєкту.

Значення, які ви задали через `/config` під старим плагіном, не переносяться. Перевірте їх у новому плагіні й задайте знову те, що ще потрібно. Усе, що лежить у `settings.json`, переїжджає разом із папкою.
