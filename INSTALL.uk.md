# Встановлення CacheGuard на комп'ютер з Windows

Усі команди — у PowerShell.

## Що потрібно заздалегідь

- **Десктопний застосунок Claude Code**, рушій не нижче 2.1.295. Перевірка версії:
  ```powershell
  Get-ChildItem "$env:USERPROFILE\.claude\projects" -Recurse -Filter *.jsonl | Sort-Object LastWriteTime | Select-Object -Last 1 | Get-Content -Tail 50 | Select-String '"version":"([^"]+)"' | Select-Object -Last 1 | ForEach-Object { $_.Matches[0].Groups[1].Value }
  ```
- **Python 3.8 або новіший і numpy.**
  - Перевірка: `python -c "import numpy; print(numpy.__version__)"`.
  - Якщо numpy немає: `python -m pip install numpy`. Ставити зі звичайного вікна PowerShell, не зсередини Claude: `pip` з Claude Desktop (збірка з Microsoft Store) ставить пакети у свою пісочницю, і звичайний Python їх не бачить.
- **Ollama з моделлю ембедингів**, потрібна для пошуку за змістом. Якщо Ollama ще немає, встановіть її з ollama.com. Потім:
  ```powershell
  ollama pull embeddinggemma
  ```
  Це близько 622 МБ. Без моделі мод працює, лише пошук іде самими словами.
- **git.**

## Встановлення

1. **Завантажити код** (гілка `master`):
   ```powershell
   git clone https://github.com/GladLuter/Claude-CacheGuard.git C:\_git\Claude-CacheGuard
   cd C:\_git\Claude-CacheGuard
   ```
2. **Знайти рушій десктопа.** `claude` з PATH — окремий CLI, часто старіший, тому потрібен саме `claude.exe` десктопа:
   ```powershell
   $CC = (Get-ChildItem "$env:APPDATA\Claude\claude-code\*\*\claude.exe", "$env:LOCALAPPDATA\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code\*\*\claude.exe" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
   Якщо нічого не знайшлося, шукати ширше (це повільно):
   ```powershell
   $CC = (Get-ChildItem $env:LOCALAPPDATA, $env:APPDATA -Recurse -Filter claude.exe -ErrorAction SilentlyContinue | Where-Object FullName -like '*claude-code*' | Sort-Object LastWriteTime | Select-Object -Last 1).FullName; $CC
   ```
3. **Встановити мод:**
   ```powershell
   & $CC plugin marketplace add C:\_git\Claude-CacheGuard
   & $CC plugin install cacheguard@cacheguard-local
   ```
   Потім перезапустити десктопний застосунок.
4. **Зібрати індекс** розмов цього комп'ютера. Першого разу це триває кілька хвилин:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py --lang uk index
   ```
   - `--lang uk` — мова повідомлень і помилок скриптів у терміналі (`en`, `ru`, `uk`); без нього вони англійською.
   - Якщо на комп'ютері вже налаштовано синхронізацію (розділ нижче), а база нова, спершу виконайте там `cg.py sync`: записи й вектори цього комп'ютера повернуться з його папки, і рахувати їх заново не доведеться.
5. **Порахувати вектори.** Це години: на i3 уся історія зайняла близько 6 годин, краще запускати на ніч. Після зупинки розрахунок продовжується з того самого місця:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py --lang uk embed --max-seconds 100000
   ```
   Далі нові записи дораховуються самі на старті сесії, до 2 хвилин за раз.
   - **Ноутбук:** на час розрахунку не давайте йому заснути. На зарядці він засинає без введення й зупиняє розрахунок. Після пробудження команду можна просто запустити знову.
   - **Вбудована відеокарта Intel (Iris Xe):** на ній разовий розрахунок іде приблизно вдвічі швидше, а вектори виходять ті самі (замір 2026-10-19 на MTLAPTOP: 2,44 довгих шматки на секунду проти 1,15 на процесорі). Ollama бачить таку карту, лише якщо її запустити з `OLLAMA_IGPU_ENABLE=1`. Для цього зупиніть звичайну Ollama в треї, потім у вікні PowerShell:
     ```powershell
     $env:OLLAMA_IGPU_ENABLE = '1'; ollama serve
     ```
     В іншому вікні запустіть розрахунок. Після нього закрийте це вікно й знову запустіть Ollama з меню «Пуск». Назавжди не вмикати: текстові моделі на вбудованій карті повільніші.
6. **Мова.** Типово мод говорить англійською: інтерфейс, правило пам'яті, описи `recall` і передача справ. Для української відкрийте файл налаштувань `%USERPROFILE%\.claude\cacheguard\settings.json` (мод створив його під час першого запуску), поставте в ньому `"language": "uk"` і наберіть `/reload-plugins`. Для російської поставте `"ru"`.
7. **Перевірити:** у новому чаті набрати `/cg-health`. Там мають бути версія, індекс, папка автопам'яті, проєкт, вектори «N з M» і рядок синхронізації.

## Спільна пам'ять двох комп'ютерів (етап 2)

Кожен комп'ютер викладає свої нові розмови, вектори й факти автопам'яті в спільну папку й забирає звідти чужі.
- Пише він лише у свою підпапку (`<папка>\<ім'я комп'ютера>\`), тому база не псується, навіть якщо обидва комп'ютери працюють одночасно.
- Без мережевої папки все працює як раніше; синхронізація наздоганяє, коли папка знову доступна.

1. **Створити папку** на мережевому диску, один раз, наприклад `\\NAS\share\cacheguard`. Сам мод її не створює: якщо диск не підключено, він покаже помилку, а не почне писати на локальний диск.
2. **На кожному комп'ютері** вказати її у файлі налаштувань `%USERPROFILE%\.claude\cacheguard\settings.json`: `"syncDir": "\\\\NAS\\share\\cacheguard"`, потім `/reload-plugins`. Зворотні скісні риски в JSON подвоюються.
3. **Перший обмін.** Уся історія — це десятки мегабайтів. Мод синхронізує не довше 60 секунд за раз і продовжує під час наступного запуску, але першого разу зручніше з термінала — спершу на i3, потім на ноутбуці:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py --lang uk sync --sync-dir \\NAS\share\cacheguard --max-seconds 3600
   ```
   Потім на i3 ще раз, щоб забрати історію ноутбука. Вектори переїжджають разом із записами: перераховувати чужі не потрібно, якщо модель ембедингів на обох однакова.
4. **Далі саме:** на старті сесії, після індексу й векторів. Вручну — `/cg-sync`, відповідь — скільки викладено й влито та помилки.
5. **Перевірити:** `recall` на ноутбуці знаходить ранкову розмову з i3, а `/cg-health` показує обидва комп'ютери й номери їхніх останніх пачок.

Що ще треба знати:
- **Коротка пам'ять** синхронізується для проєкту поточного чату.
  - Факти, створені на цьому комп'ютері, ідуть у спільну папку.
  - Чужі копіюються в папку автопам'яті, якщо їх там немає, і до `MEMORY.md` додається рядок-покажчик.
  - Власний файл із тим самим ім'ям ніколи не перезаписується: чужа версія лягає поруч як `ім'я--КОМП'ЮТЕР.md`. Влитий факт, який ви видалили, не повернеться.
- **Проєкт** розпізнається за шляхом без домашньої папки: `C:\Users\AIJ\work\x` і `C:\Users\gladl\work\x` — один проєкт. Шляхи поза профілем (`C:\_git\…`) збігаються й так.
- **Зіпсована пачка** (обрив мережі, збій диска) зупиняє прийом лише від її комп'ютера, помилку видно в `/cg-health` під час кожної синхронізації. Якщо пачку не відновити: `/cg-sync skip <комп'ютер> <номер>`. Пропуск видно в `/cg-health`.
- **Видалити запис** (наприклад, секрет, який фільтр пропустив) можна лише явно, і видалення дійде до іншого комп'ютера:
  ```powershell
  python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py forget --conv <id розмови> --pos <pos>
  ```
  `conv` і `pos` — з рядка знахідки `recall`. Більше нічого з індексу не зникає: ні під час перебудови, ні коли Claude Code переписує чи видаляє транскрипти.

## Стиснення пам'яті (етап 3)

Мод стискає те, що сам кладе в контекст моделі: видачу `recall` і `recall_more` та цитати розмови в передачі справ. Стиснення механічне, без викликів моделі. Код, шляхи, посилання, числа, імена й заперечення не чіпаються.

- **Рівень:** ключ `"compression"` у файлі налаштувань `%USERPROFILE%\.claude\cacheguard\settings.json`, потім `/reload-plugins`.
  - `off` — без стиснення;
  - `lite` — пробіли й розмітка;
  - `full` — плюс службові слова;
  - `ultra` — плюс пунктуація й великі літери (типово).
- **Подивитися, що робить рівень**, на будь-якому тексті:
  ```powershell
  python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py compress --level ultra --file нотатка.txt
  ```
- **Скільки пам'яті в контексті:** `/cg-stats` пише в нотатку розділ «Пам'ять у контексті» — правило пам'яті, `MEMORY.md`, результати `recall` та їхня вартість, передачі справ. `/cg-health` показує рівень стиснення й розмір `MEMORY.md`.
- Якщо працівник гірше розуміє стиснені уривки, поставте `full` або `lite`.

## Уроки, фонове завдання, пошук помилок (етап 4)

Після `git pull` і `/reload-plugins`:

1. **Один раз перебудувати індекс**, щоб у нього потрапили помилки інструментів зі старих розмов:
   ```powershell
   python C:\_git\Claude-CacheGuard\plugin\scripts\cg.py index --rebuild
   ```
   Перебудова лише додає відсутнє. Вектори для нових записів дорахує фонове завдання або наступний запуск чату.
2. **Увімкнути фонове завдання** на кожному комп'ютері: у чаті `/cg-job on` (або `/cg-job on 15` — раз на 15 хвилин).
   - З'явиться завдання «CacheGuard» у Планувальнику завдань: без вікна, лише поки ви ввійшли в систему, на батареї вектори чекають на мережу.
   - Налаштування воно бере з того самого файлу `settings.json`, що й мод.
   - `/cg-job` показує стан і останній запуск, `/cg-job off` видаляє завдання.
   - Якщо завдання не запускається, перевірте, що Python установлено з python.org (поруч з `python.exe` має лежати `pythonw.exe`).
3. **Уроки** працюють самі: працівник зберігає зрозумілу помилку через `lesson_save`. `/cg-lessons` показує уроки проєкту, `/cg-lessons forget <pos>` видаляє урок.
   - Урок приходить до повідомлення, близького за змістом, і один раз зупиняє команду з його тригером.
   - Якщо уроки приходять не до речі, підніміть `lessonsMinScore` у `settings.json` до `0.55`; якщо не приходять ніколи — опустіть до `0.4`. Вимкнути — `"lessons": false`.

## Шифрування (етап 5)

За бажанням і лише у Windows. Шифруються індекс (з його резервною копією `index.before-stage2.db`) і все, що комп'ютер кладе в папку синхронізації. У папці читаються ім'я комп'ютера, номери, кількість і розміри пачок, а в мітці покоління (`gen-0001\generation.json`) ще назва способу шифрування, відбиток ключа й дата. За відбитком ключ не дізнатися.
- Ключ лежить у `settings.json` під захистом Windows (DPAPI). На іншому комп'ютері або під іншим обліковим записом Windows цей файл ключа не дасть.
- Поки ви не набрали `/cg-encrypt on`, у вас нічого не змінюється.

**Способи шифрування.** Індекс і папка синхронізації шифруються кожен своїм способом, і кожен комп'ютер обирає їх сам:
- Індекс, ключ `indexCipher`:
  - `sqlcipher` (типово): SQLCipher, потрібен пакет `sqlcipher3`;
  - `efs`: шифрування файлів самою Windows. Потрібні Windows Pro (або Enterprise, Education) і диск NTFS. Пакети ставити не треба. Під EFS іде вся папка мода `%USERPROFILE%\.claude\cacheguard` і папка індексу, якщо вона інша: індекс, журнал, резервні копії, передачі справ, `settings.json`, `forgotten.json`.
- Папка синхронізації, ключ `shareCipher`:
  - `sqlcipher` (типово): SQLCipher, потрібен пакет `sqlcipher3`;
  - `cryptography`: AES-GCM, вбудований у Windows (`bcrypt.dll`), пакети не потрібні. Пакет `cryptography` більше не потрібен.
- **Smart App Control** може не дати завантажити `sqlcipher3`: його модуль не підписаний. Під ним годяться тільки `efs` і `cryptography`, а комп'ютер із цією парою `sqlcipher3` не завантажує жодного разу.
- Свою підпапку в папці синхронізації кожен комп'ютер пише своїм способом, а чужі читає за міткою покоління. Якщо чужу підпапку записано SQLCipher, а тут `sqlcipher3` не завантажується, `/cg-health` називає той комп'ютер і радить перевести його на AES-GCM.

1. **Обрати способи** на кожному комп'ютері в `%USERPROFILE%\.claude\cacheguard\settings.json`. Наприклад, EFS і AES-GCM:
   ```json
   {
     "indexCipher": "efs",
     "shareCipher": "cryptography"
   }
   ```
   Якщо нічого не обирати, в обох лишається `sqlcipher`. `/cg-encrypt on` і `join` беруть способи з цього файлу й записують їх назад поруч із ключем.
2. **Поставити пакет `sqlcipher3`**, лише якщо він потрібен: для способу `sqlcipher` (індексу чи папки) і один раз для переведення вже зашифрованого індексу SQLCipher в EFS. Ставте на кожному комп'ютері зі звичайного вікна PowerShell, не зсередини Claude: `pip` з Claude кладе пакети у свою пісочницю, і фонове завдання їх не побачить.
   ```powershell
   python -m pip install sqlcipher3
   ```
   Для `efs` і `cryptography` цей крок не потрібен.
3. **Перший комп'ютер:** `/reload-plugins`, потім `/cg-encrypt on`. Вікна «Claude-CacheGuard» можуть опинитися за іншими вікнами.
   - З `efs` команда спершу перевіряє, що диск уміє EFS. Якщо ні (Windows Home або диск не NTFS), вона відмовить до створення ключа, нічого не змінивши.
   - У першому вікні буде **код відновлення**. Він показується один раз. Ctrl+C копіює текст вікна: вставте код у менеджер паролів. Без нього зашифровану історію не прочитати, якщо зникнуть комп'ютери або їхні облікові записи Windows.
   - Питання «Код відновлення збережено?»: типово «Ні». Шифрування почнеться лише після «Так».
   - Індекс і його резервна копія шифруються. З `sqlcipher` відкриті копії (`index.db.plain`) видаляються лише після «Так». Після «Ні» вони лишаються, і `/cg-encrypt on` запитає знову.
   - З `efs` папка мода і папка індексу йдуть під шифрування Windows, а індекс SQLCipher стає звичайною базою під EFS зі сторінками 16 КБ. Відкритої копії поза EFS не буває, тому питання про `index.db.plain` немає.
   - Папка синхронізації: комп'ютер викладає свою підпапку заново, обраним способом. Колишні дані в ній (відкриті або іншим способом) видаляються лише після «Так» і лише коли нові викладено повністю.
4. **Другий комп'ютер:** `git pull`, `/reload-plugins`, свої способи в `settings.json` (крок 1), `/cg-encrypt join`. Код відновлення вводиться у вікні зі схованим вводом. Ключ один на всі комп'ютери, тому `on` на другому відмовить і підкаже `join`.
   - Якщо на першому комп'ютері ви змінюєте спосіб папки (наприклад, SQLCipher на AES-GCM), приєднуйте другий лише після цього. Інакше він побачить покоління SQLCipher, яке під Smart App Control не відкриє.
5. **Перевірити:** `/cg-health` на обох комп'ютерах пише, наприклад, «Шифрування: ввімкнено (індекс: EFS, папка синхронізації: AES-GCM)». У дужках названо способи індексу й папки: SQLCipher, EFS або AES-GCM. Якщо щось не доведено до кінця, рядки під нею скажуть, що повторити. Лише стан показує `/cg-encrypt status`.

Що ще треба знати:
- **Команди:** `/cg-encrypt on | join | off | status`. Без аргумента виконується `status`.
  - `off` розшифровує індекс (з EFS знімає шифрування Windows з обох папок), викладає підпапку цього комп'ютера відкритою й прибирає ключ із `settings.json`. Вимикати треба на кожному комп'ютері. Новий `on` створює новий ключ, решта комп'ютерів приєднуються заново.
  - Втратили ключ (інший обліковий запис Windows, перевстановлення): `/cg-encrypt join` з кодом відновлення.
  - Втратили і ключ, і код: цей комп'ютер своє зашифроване вже не прочитає. Вимкніть шифрування (`off`) на решті комп'ютерів і вручну видаліть теку цього комп'ютера в папці синхронізації, а якщо на ньому лишився зашифрований `index.db`, то й його (мод збере новий з розмов на диску). Потім увімкніть шифрування заново: `on` на одному комп'ютері, `join` з новим кодом на решті.
- **Поки другий комп'ютер не приєднався**, перший нічого від нього не бере, а `/cg-health` називає його: «виконайте на ньому `join`». Історія другого не губиться: після `join` він викладе її зашифрованою.
- **Межа часу.** Один запуск обмежений приблизно 10 хвилинами (межа десктопного застосунку). Велике перше викладання може не вкластися: відповідь скаже, що не закінчено. Повторіть `/cg-encrypt on` (або `join`): команда продовжить з того місця, де зупинилася. Будь-який крок можна безпечно повторити. Решту викладе й фонове завдання, але колишні відкриті дані з папки видалить лише повтор команди, після «Так».
- **Способи шифрування** задають ключі `indexCipher` (`sqlcipher` типово або `efs`) і `shareCipher` (`sqlcipher` типово або `cryptography`, тобто AES-GCM) у `settings.json`. `/cg-encrypt on` і `join` самі записують їх у файл, а файл має пріоритет над `/config`, тому згодом змінюйте їх у файлі, потім `/reload-plugins` і `/cg-encrypt on`. Чужі дані комп'ютер читає будь-яким способом, який уміє відкривати сам: SQLCipher лише за встановленого `sqlcipher3`.
- **Швидкість.** На зашифрованому індексі `recall` повільніший приблизно на 0,08 с (замір 2026-10-27, 24,7 тис. векторів). Різниця росте разом із кількістю векторів. Замір 2026-11-02 на копії справжнього індексу (25,3 тис. векторів, медіана 20 запусків): один пошук займає 290 мс із SQLCipher і 170 мс з EFS, в обох випадках сторінки 16 КБ.
- **Що приймається разом з EFS:**
  - Копія індексу на флешку FAT чи exFAT, у мережу або через `copyfile` виходить відкритою. Сам мод індекс назовні не копіює.
  - Файли відкриваються лише під тим самим обліковим записом Windows. Якщо індекс під EFS не відкривається (інший користувач, втрачено сертифікат), мод скаже про це й новий порожній індекс поверх не створить.
  - Якщо перевстановити Windows без резервної копії сертифіката, старий індекс не відкрити. Видаліть його, і мод збере новий з розмов на диску. Копія сертифіката за бажанням, мод її не робить. Щоб зробити її, виконайте `cipher /x <файл>`: Windows запитає пароль і збереже сертифікат EFS та ключ у файл `.pfx`, захищений цим паролем.
  - Файл, який тримає відкритим чат або фонове завдання, EFS не зашифрує: команда скаже, що файли зайняті. Повторіть її за хвилину.
- **Лишається відкритим:**
  - розмови Claude Code, `%USERPROFILE%\.claude\projects\*.jsonl`;
  - файли автопам'яті кожного проєкту на локальному диску (`.md`): їх читає Claude Code;
  - передачі справ, тека `handoffs` поруч з індексом: той самий текст іде в чат відкритим. З EFS самі файли на диску зашифровані.
  - `forgotten.json` у `%USERPROFILE%\.claude\cacheguard`, його створюють лише для індексу в іншій теці: ключі записів, видалених через `forget`. Це хеші, тексту в них немає.

## Індекс в іншій папці

Для комп'ютера, де на C: мало місця. Індекс росте з кожним чатом, і його можна перенести на інший локальний диск. Лише Windows. Без цієї команди нічого не змінюється, індекс лежить у `%USERPROFILE%\.claude\cacheguard\`.

1. **Переїхати:** `/cg-index-dir D:\CacheGuard`. Без шляху відкриється вікно вибору папки.
   - Команда копіює індекс, звіряє копію і лише після цього перемикає мод на нову папку. Якщо індекс зайнятий чатом або фоновим завданням, вона просить повторити за хвилину.
   - Потім вікно питає, чи видалити стару копію. Типово «Ні». Старі файли видаляються лише після «Так». Після «Ні» вони лишаються, а `/cg-health` нагадує, де вони лежать. Щоб запитати знову, повторіть `/cg-index-dir` з тією самою папкою.
2. **Перевірити:** `/cg-health`. У рядку «Індекс» тепер новий шлях, наприклад `D:\CacheGuard\index.db`.

Фонове завдання та інструменти `recall` і `lesson_save` самі працюють з новою папкою. Нічого перевстановлювати не треба.

Що ще треба знати:
- **Що переїжджає:** `index.db`, його резервна копія `index.before-stage2.db` (якщо є), папка `handoffs` і `job.xml` фонового завдання. Зашифрований індекс переїжджає зашифрованим. Індекс під EFS лишається під EFS: цільова папка шифрується до копіювання.
- **Що лишається на C:** файл `settings.json` (у ньому ключ шифрування і новий рядок `indexDir`) та розмови Claude Code, `%USERPROFILE%\.claude\projects`.
- **Відмова.** Команда нічого не змінює і називає причину, якщо:
  - папка не на локальному незнімному диску (мережеві шляхи, мережеві та знімні диски не підходять) або лежить усередині OneDrive
  - у папці вже є інший `index.db`, чужу базу команда не перезаписує
  - на цільовому диску не вистачає місця (потрібен розмір файлів індексу і ще 200 МБ)
  - поруч з індексом лежить `index.db.plain`, спершу доведіть до кінця `/cg-encrypt on`
  - індекс під EFS, а диск папки не вміє шифрувати файли (потрібен NTFS): оберіть папку на диску NTFS або спершу вимкніть шифрування (`/cg-encrypt off`)
  - на C: ще не злито записи за час, поки папки не було (див. нижче).
- **Якщо папки або `index.db` у ній не стало** (диск відключили, папку видалили), мод каже про це сповіщенням, один раз за сесію, і рядком у `/cg-health`: «індекс у D:\CacheGuard недоступний, зараз працюю з …». Він працює з індексом на C:, а `indexDir` не змінює.
  - Якщо у стандартній папці вже лежить індекс (стара копія після «Ні»), робота йде з ним. Якщо ні, новий створюється лише коли на C: вільно щонайменше 2 ГБ. Інакше команди, яким потрібен індекс, відповідають помилкою зі шляхами й цифрами, і нічого не створюється. Команди без індексу працюють: передача справ кнопки «Новий працівник», підрахунок токенів і попередній перегляд стиснення. Поки так, у рядку стану стоїть «Індекс недоступний, подробиці в /cg-health», а на кожне ваше повідомлення приходить сповіщення з причиною.
  - Синхронізація йде як і раніше.
  - Видалене через `forget` лишається видаленим і на C:. Його ключі лежать у `forgotten.json` поруч з `settings.json`, і індекс на C: застосовує їх раніше, ніж прочитає хоч одну розмову.
- **Коли папка повернулась**, перший же запуск `cg.py` (фонове завдання або команда в чаті) сам вливає в неї все, що назбиралося на C:, і видаляє тимчасовий індекс. Без питання, місце на C: дорожче. Стара копія, яку ви залишили відповіддю «Ні» і яка замінювала індекс на час збою, вливається й видаляється так само. Повідомлення називає кількість влитих записів, і `/cg-health` її зберігає. Видалене через `forget` не повертається. Якщо злиття не зійшлося, обидва індекси лишаються на місці, робота йде з папкою індексу, `/cg-health` показує причину, а наступний запуск пробує знову.
- **Папка не повернеться.** Поки мод працює з C:, команда з повним шляхом стандартної папки, `/cg-index-dir C:\Users\<ім'я>\.claude\cacheguard`, прибирає `indexDir` і нічого не копіює. C: стає постійним місцем індексу. Якщо папка повернулась, а індексу в ній немає, команда зі шляхом цієї папки переносить індекс з C: у неї.
- **Повернути індекс на C:** з робочої папки його переносить та сама команда, `/cg-index-dir C:\Users\<ім'я>\.claude\cacheguard`. Якщо на C: лишилась стара копія, що не збігається з індексом байт у байт, команда відмовить. Тоді спершу повторіть `/cg-index-dir` з робочою папкою і дайте відповідь «Так» на питання про видалення. Копія, що збігається байт у байт, переїзд не зупиняє.
- **Злиття не виходить раз за разом.** `/cg-health` показує причину у своєму рядку, а `/cg-index-dir` відмовляє, поки злиття не зроблено. Якщо причина повторюється щоразу, видаліть `index.db` у `C:\Users\<ім'я>\.claude\cacheguard` вручну, але лише коли збережені там записи вже не потрібні. Індекс у робочій папці лишається як є.

## Корисно знати

- **Мод читається просто з папки репозиторію.**
  - Тримайте її на гілці `master`. Якщо раніше була `stage1`, один раз виконайте `git checkout master; git pull`.
  - Після `git pull` наберіть у Claude Code `/reload-plugins`: перевстановлювати не потрібно.
- **Індекс і вектори** лежать у `%USERPROFILE%\.claude\cacheguard\index.db` і в репозиторій не потрапляють. Кожен комп'ютер веде свою базу; спільна папка синхронізації — лише обмін пачками між ними.
- **Якщо індекс переїхав** командою `/cg-index-dir`, він лежить у вибраній папці (див. «Індекс в іншій папці»).
- **`/cg-index rebuild`** перечитує всі транскрипти й додає лише те, чого бракує: вектори лишаються, нічого не видаляється.
- **Налаштування:** свій файл `%USERPROFILE%\.claude\cacheguard\settings.json`, по одному на комп'ютер. Він лишається в цій папці, навіть коли індекс переїхав. Ключі: `language`, `compression`, `syncDir`, `bandMinTokens` і `bandIdleMinutes` (пороги смуги), `showLimits` (рядок лімітів), `python` (команда Python, якщо це `py`, а не `python`), `embedModel`, `lessons` і `lessonsMinScore` (уроки), `indexCipher` (шифрування індексу), `shareCipher` (шифрування папки синхронізації), `indexDir` (папка індексу). Таблиця типових значень лежить у [README.uk.md](README.uk.md).
  - Мод створює файл під час першого запуску з усіма поточними значеннями, лишається відкрити й поправити. У файлі можна лишити тільки ті ключі, які ви змінюєте.
  - Мод читає файл при кожному завантаженні: на початку чату й за `/reload-plugins`. Після правки наберіть `/reload-plugins`.
  - Значення з файлу мають пріоритет над `/config`. У десктопному застосунку для модів немає вікна налаштувань, тому налаштування лежать у файлі. `/config` у терміналі `claude` і далі працює, але за розбіжності перемагає файл.
  - Зворотні скісні риски в JSON подвоюються: `"Z:\\cacheguard"`.
  - `/cg-health` показує рядок зі шляхом до файлу.
  - Рядок `encryptionKey` пише сам мод: це ключ шифрування під захистом Windows. Не правте його.
  - Рядок `indexDir` пише команда `/cg-index-dir`. Руками його не правлять: файли індексу самі не переїдуть.
  - Якщо файл зіпсований (хибний JSON), мод покаже сповіщення з іменем файлу й залишить значення з `/config`. Невідомий ключ або значення не того типу дає таке саме сповіщення, а цей ключ пропускається.
- **Смуга над полем вводу** — одна область для всіх модів. Смуга CacheGuard малюється у своїй рамці із заголовком, а смуги інших модів лишаються під нею.
- **`/cg-stats`** пише заміри в Obsidian через MCP-сервер `obsidian`. Він має бути підключений на цьому комп'ютері. Якщо Obsidian недоступний, замір чекає в черзі й іде під час наступного запуску.
